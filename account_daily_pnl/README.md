# 三账户场内持仓与盈亏

继续开发 PnL 第二步时，从 [项目交接](PROJECT_HANDOFF.md) 进入。日常使用按本页操作。

## 公司每天点击一次

更新公司仓库后，登录 Wind、接通可访问 BCT 的公司网络，双击仓库根目录的 **收益统计.cmd**。它用公司 `swhy_delta1` 处理前一交易日，同时补齐漏跑的交易日并生成 Excel 和收益图片。原来已跑通的历史数据和本机加密登录设置会自动复用。

| 情况 | 操作 |
| --- | --- |
| 每天运行 | 双击根目录 **收益统计.cmd**。检查到前一交易日，账户报表更新到当前数据能算到的最近交易日。 |
| 停跑几天，或下载和运行中断 | 公司网络及 Wind 恢复后，再双击同一入口。已有 BCT 归档和 Wind 行情会复用，缺的交易日按顺序补下载、补算。 |
| 单独复查某天 | 在仓库根目录运行 `.\收益统计.cmd --only-day --date 2026-11-18`，日期替换为所需交易日。 |

升级后首次运行会用已有 Excel 建立日终持仓缓存。此后根据流水文件指纹识别更正，并从受影响的交易日继续。修改行情或资金输入时只更新受影响的估值。日终缓存为数据目录的 `daily_cache.json`。Wind 缓存在同一数据目录的 `wind/`，按标的、交易日和价格字段识别，已有同口径价格直接读本地，缺项按精确日期查询。

之前本程序保存的 `wind/YYYY-MM-DD.xlsx` 可直接复用。将新旧运行指向同一个数据目录，程序会按相同的标的、交易日和字段匹配。日志打印实际使用的 Wind 缓存目录及三个计数：

- 「Wind 本地复用」是本次估值从原缓存读出的报价。
- 「Wind 新下载并保存」是本次成功取到并写入缓存的报价。
- 「Wind 仍待补」是本次所需、仍没有可用的报价。若整段直接沿用已有盈亏，窗口会显示「Wind 新下载并保存 0 项」。

需要看到具体标的、日期和字段时，在仓库根目录执行 `.\收益统计.cmd --wind-log-detail`。明细按交易日归组，每项代表一个标的在当天的一个价格字段。

公司机首次运行缺少加密设置时，程序会查找「下载」及其 Chrome、IDM 子目录和项目本机目录中的原 BCT 脚本或 `1.zip`。自动找到后会使用原账号并加密保存。只有没找到来源才弹一次文件选择，选原脚本或原始 `1.zip` 即可。Windows 加密设置归当前机器和用户所有。历史包也可放在「下载」或 `account_daily_pnl` 目录，已导入的机器直接复用。

## 可选的工作台定时日更

1. 在公司 Git 根目录执行 `git pull --ff-only`。已经跑通单日测试的，可直接复用原数据目录里的历史 Excel。如果尚未导入历史，把 `account_daily_pnl_history.zip` 放到项目目录，与启动文件同级。
2. 登录 Wind，接通可访问 BCT 的公司网络，双击 **setup-daily.cmd**。首次会复用本机已有 BCT 设置或下载脚本，找不到时弹窗选择原来的 `download_trading_flow_add_holdexcel.py`、`download_trading_flow.py` 或附件原始 `1.zip`。程序验证登录后，用当前 Windows 用户加密保存凭据。
3. 在已有的 **工作自动化工作台 → 定时子任务** 登记或更新「三账户场内持仓与盈亏」，每天北京时间 **09:25** 运行，开启错过后自动补跑。完整生成后由工作台邮件队列发送汇总 Excel 和图片给 meiyifan@swhysc.com，图片同时显示在邮件正文中。同一内容重复运行复用已归档附件及发送键。登记后立即试跑前一交易日，试跑只生成文件。工作台后台和原有邮件服务需正常运行。

日常由工作台调用 `workbench_entry.py`。需要手动出表时双击 **start.cmd**。回退到最近可对账交易日仍正常生成邮件结果，邮件主题和附件使用实际对账日。日志末尾显示计划检查日、账户截止日、策略台对账日，以及邮件结果是否已交给工作台。实际入队和投递状态在工作台查看。

已登记的老任务可能仍调用 `start.cmd` 或 `收益统计.cmd`，程序结果邮件为「不处理」。Git 更新只更新程序文件。在公司仓库根目录运行 `.\account_daily_pnl\setup-daily.cmd --register-only`，即可在原任务 ID 下登记 `workbench_entry.py` 和「成功后发送」，沿用原数据和输出参数。这个命令只登记任务。登记后在工作台运行该任务，日志应显示「邮件结果已交给工作台」。

结果默认在仓库根目录 `outputs/account_daily_pnl/`，包含 `场内账户_交易日.xlsx`、`逐交易日统计.xlsx` 和两张收益图。

工作台路径非默认时，从仓库根目录执行 `.\account_daily_pnl\setup-daily.cmd --work-root "工作台目录"`。已有工作台任务的时间可直接在「定时子任务」编辑。正式总权益需要公司结算权益和已核实的入出金，见下文报表口径。

## 公司只测一天

1. 在公司 Git 根目录执行 `git pull --ff-only`。
2. 把单独交付的 `account_daily_pnl_history.zip` 放到本目录，与 `test-yesterday.cmd` 同级。首次运行会核验并导入到本机的 `data/account_daily_pnl`。已下载文件按哈希复用。
3. 打开本机 Wind 终端并确认已登录。双击 **test-yesterday.cmd**。它优先续用已有日终持仓，只导出前一个交易日的报表。默认报表位置为仓库根目录的 `outputs/account_daily_pnl/场内账户_YYYY-MM-DD.xlsx`。窗口会显示日期、续算进度和保存位置，按键后关闭。

本次历史包截止 2026-11-18。以后要复测该日，可以在本目录执行 `.\test-yesterday.cmd --date 2026-11-18`。使用 11 月 18 日包测试 11 月 18 日时，BCT 流水和快照均可本地读取，Wind 用于缺少的前一交易日价格。若测试日超过数据包截止日，则按以下日更方式增量下载。

启动入口复用公司已有的 `swhy_delta1` Python（默认 `D:\conda\envs\swhy_delta1\python.exe`），窗口首行显示实际解释器路径。程序依赖 requests、openpyxl 和时区数据。首次从原始 ZIP 直接导入旧版 XLS 时还需要 xlrd。如果 WindPy 装在另一 Python 里，把 `config.example.json` 复制到数据目录的 `inputs/config.local.json`，填写本机的 `wind_python` 解释器路径。

## 正式日更和中断补跑

- 日常手动运行统一用根目录 **收益统计.cmd**。本机 BCT 设置可通过 `inputs/config.local.json` 的 `bct_script` 或 `BCT_CREDENTIALS_SCRIPT` 指向既有可信脚本。也支持本机环境变量 `BCT_USERNAME` 和 `BCT_PASSWORD`。
- 以北京时间取当天之前最近的交易日。程序从基准起核对交易流水存档，缺几天补几天。历史快照只补已结束月份的最后交易日。正常日更自最近成功下载日恢复，停跑期间遗漏的交易日逐日下载快照、流水和生成报表。节假日和周末按 [交易日历](../dashboard/marketdata/trading_calendar.py) 跳过。
- 自动日更从连续流水覆盖范围内选最近一个三账户日净盈亏均可计算的交易日。如果当前只能算到 T−2，就以 T−2 发布账户 Excel、JSON 和图；下一次运行继续补新交易日。总权益的待核实状态单独记录。指定 `--date` 或 `--only-day` 时按指定或默认交易日复查账户。
- `flows/`、`snapshots/`、`wind/` 分别保存按业务日命名的原始流水、BCT 快照和 Wind 缺价补录 Excel。BCT 的账簿和日期从接口校验，分页核对 `totalCount`。无成交的交易日保留有表头和零行元数据的有效流水文件。下载中断后，下一次运行复用已保存文件，继续缺项。源归档和正式报表逐文件原子写入。
- 日更续算新增及改动的交易日，再用缓存汇总更新 `逐交易日统计.xlsx`、`历史至今_账户收益.png` 和目标年份的收益 PNG。统计表含「收益概览」「逐交易日统计」「今年逐日」，图片含三个账户与合计的单日、累计净盈亏。图表使用公司已有的 QtGui。缺行情时曲线留断点，区间的盈亏和费用覆盖日数在 Excel 中查看。
- 需要指定统计日时，从仓库根目录运行 `python -m account_daily_pnl --date YYYY-MM-DD`。`--only-day` 只写该天报表，累计收益率由全量日更生成。`--prepare` 只准备输入 Excel，`--no-download` 和 `--no-wind` 用于离线核验。

## 报表口径

| 内容 | 计算 |
| --- | --- |
| 持仓 | 从 2025-12-29 日终滚动，2602 使用 BCT 5102 组合、5526 使用基准、5524 从空持仓起算。期货用买卖方向加开平记多空两边。送转入数量，现金分红入盈亏。 |
| 单日净盈亏 | 前后两日有结算单权益且资金流水已核对时，采用当日总权益 − 上日总权益 − 当日净入金。其余交易日用成交估值净盈亏。报表单列权益法盈亏、成交估值费前和净盈亏、当日手续费及结算权益差与成交估值的对账差额。 |
| 成交估值 | 今日日终净持仓价值减前一交易日日终净持仓价值，加卖出成交额、减买入成交额、加现金分红、减手续费。期货同一合约用相同乘数。隔夜仓以昨结为当日起点，新开仓按成交价与今结之差，同日开平按卖价与买价之差。现金分红与送转按流水业务日入账。 |
| 手续费 | 优先逐笔累计原始 `fee`，缺值时用可核对的费前、费后金额反推。结算权益已计入手续费，成交估值扣一次原始手续费。 |
| 价格 | BCT `instrumentQuote` 优先，缺项按实际交易日向 Wind 查询。默认现货为 `close`，期货为 `settle`，核对公司 BCT 估值口径后可用 `wind_futures_field` 改为 `close`。跨来源的期货价格会提示核对。 |
| 总权益 | 优先使用结算单总权益。也可用确认的基准权益 + 累计净入金 + 成交估值累计净盈亏推算，并标为模型权益。每账户填 `opening_equity` 及 `cash_flows_confirmed_through`（已核对入出金的截至日）。通过 `cash_movements` 列入实际归属交易日 `date`、`account`、`net_deposit`，出金用负数。 |
| 参考权益 | 基准表中的基金净值或本机配置值，加已登记资金流和计算盈亏，在资金覆盖或基准权益待确认时提供参考。5524 空仓不代表期初资金为零。 |
| 收益率 | 当日净盈亏除以上日总权益与按时间加权的外部资金合计。资金明细可填 `weight` 作为当日在账时间比例，开盘前到账填 1，收盘后到账填 0。时点未知的资金变动日及依赖该日的区间收益率留空。逐日收益率按几何连乘，今年按目标日所属年份重置。 |
| 累计净盈亏 | 历史从基准日收盘起算，今年以前一年最后一个交易日日终为起点。两个区间端点的结算权益和资金流水都齐全时，用扣除区间净入金的权益变化。其余情况用同口径的成交估值端点。 |

要导入结算权益，在数据目录 `inputs/账户总权益.xlsx` 的第一个工作表提供「交易日」「账户」「总权益」三列。账户填 2602、5526 或 5524，同账户同交易日一行。基准日和报告日均可录入。入出金和覆盖日期从 `inputs/config.local.json` 读取。

表内的期货名义额用于查看敞口。BCT 持仓快照按交易簿归集，报表的「数据检查」使用三个账户的净持仓与账簿快照对照，差异保留供核对。

## 给后续收益统计使用的数据

账户收益是收益统计入口的第一项。完整日更在报表目录写入 `account_daily_pnl.json`。后续统计用 `account_daily_pnl.series.load_series(path, required_through=目标交易日)` 读入已校验的第 1 版结果，无需重读 BCT 流水或解析 Excel。

- 主键为 `trading_date` 和 `account_id`，账户是 2602、5526、5524。账户字段为字符串，`total` 是已计算的合计行。按单账户求和时取三个账户行。
- `net_pnl` 是报表采用的净盈亏，另有独立的成交估值和权益法结果、`fee`、`closing_equity`、净入金及历史、今年累计值。金额以人民币元表示，收益率小数 `0.01` 表示 1%。金额和收益率是十进制字符串，可用 Decimal 读取。
- `null` 表示缺数据或口径待确认。每行附盈亏来源、权益来源和状态。文件标明基准日及 `through` 截止交易日，后续统计可要求日期匹配，避免误用旧结果。单日测试模式只写该日报。

## 第二步 · 策略台合约收益

完整日更会检查收益互换日报并更新 `data/account_daily_pnl/swap_report_status.json`，下一任务可读取该状态及其指向的已校验归档。独立检查可运行 `python -m account_daily_pnl.swap_report`。默认检查公司共享来源及本地归档，`--local-only` 只查本地。

完整日更会在发布账户收益 JSON 后生成 **策略台PnL对账.xlsx** 和 **策略台PnL对账.png**，默认同存于 `outputs/account_daily_pnl/`。公司使用原入口 **收益统计.cmd** 即可。已有工作台日更也会一并生成。策略台日报默认复用「日报管理」的公盘来源和本地归档，首次从可用来源回补缺少的历史交易日报。手动下载者可用 `.\收益统计.cmd --strategy-source-dir "日报目录"`。支持补跑指定交易日。`--no-download` 仅使用已有文件。`--only-day` 和 `--skip-strategy` 可单独复核账户。

对账在账户收益实际截止日内，选择最近一个既有可读策略台日报又有同日 5526 日净盈亏的交易日。例如账户已更新到 T−1，策略台只有 T−2 时，对账表、图和邮件均使用 T−2。没有可对账的交易日时保留已有对账文件和本次账户结果，日志列出待补原因，完整任务返回状态码 2。

对账工作簿包括当日和年内累计汇总、逐交易日序列、年度汇总、最新合约起始日小计和数据检查。全部 ETF 拆为四指数 ETF 和其他 ETF，合计只加一次。差额取 5526 实盘净 PnL 减 Excel 股指期货 PnL。替换后合计保留个股与全部 ETF，并使用 5526 实盘净 PnL。

Excel 日 PnL 取相邻交易日报的已实现及待实现余额差。年内累计取报表余额与上年末交易日报之差，需使用同一报表覆盖和累计口径。2025 年仅覆盖账户基准日收盘以后。若缺目标日报、相邻日报、年末基准或 5526 数值，相关结果留空，已有结果仍会生成。账户使用第一步导出的 `net_pnl` 与 `ytd_net_pnl`。

### 单份日报复核

在仓库根目录用公司收益统计的 Python 运行 `python -m account_daily_pnl.strategy_pnl`。先调用已有的 D1 策略台日报同步，再检查不晚于前一交易日的最近可读日报，校验「总表」J5 与文件名日期。指定 `--source-dir "日报目录"` 可直接检查手动下载的文件。复核历史单份文件时用 `--workbook "D1策略台日报_YYYY-MM-DD.xlsx"`，加 `--output "统计.json"` 可保存复核结果。

- 读取「合约信息」第 2 行的列名，仅取交易对手名称为「策略部交易台」的行。按报告日汇总，同时保留各起始日的小计。同一合约的多条明细逐行统计。
- 股指期货限 IF、IH、IC、IM。ETF 根据标的名称和证券代码识别，个股按可识别的境内股票代码统计。无法分类的行可在输出的 `unclassified` 中查看。ETF 专项取上证50、沪深300、中证500和中证1000，为全部 ETF 的子集。
- 已实现及待实现各取相应的资产收益和利率收益结算货币列，按表内符号汇总。预付金返息列单列于源表，本期统计口径为资产与利率两项。当前汇总采用人民币元，必需金额缺失或交易币种待核对时提示具体行。
- 默认写入报表目录的 `strategy_contract_pnl_YYYY-MM-DD.json`。输出含总计、四指数 ETF 分项、起始日小计、原日报指纹及第一步账户序列的日期覆盖。合约收益当前来自该日报，后续合并账户统计时再按报表日期匹配第一步数据。
