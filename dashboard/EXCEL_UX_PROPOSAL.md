# 数字 Excel：数据补齐与精简首页评审方案

2026-10-20，用户认可样例并授权实施及推送。现已接入四卡概览、25项简洁指标页、原生图表和历史选择/网络向导；原400行指标及来源完整保留。公司DDB允许之后配置，未配置时可使用现有数据。当前使用步骤见 [NUMERIC_EXCEL.md](NUMERIC_EXCEL.md) 和 [COMPANY_SETUP.md](COMPANY_SETUP.md)。下面保留数据核查与设计依据；其中“待实施/建议”记录的是评审时背景，以本段及交接的实际实现/验证为准。公司最新具体HEAD仍是此前确认的60e5446，不能从远端推送推断已更新。

## 先解释数据，而不是改变指标

开发机按历史发布清单核对两个短文件名包与当前本地历史：每个包的12,567个分片，逐项比较instrument、frequency、trade_date、sha256，集合完全一致。不是仅比较文件名或最后日期。两者均覆盖2025-07-01至2026-10-16；指数日线/分钟各1,256个分片，期货日线5,024个、分钟5,031个。

公司返回的配置使用第一版短包 `imports/20261019_short/index` 和 `futures`；v2目录命名不同，但上述历史内容清单一致。没有证据需要公司重导v2来修复指标。这里没有读取公司磁盘逐文件验签，因此不宣称公司安装后文件已经全部核验。开发机证据保存在忽略目录 `.deps/numeric_ui/history_audit.json` 和 `package_compare.json`，不发布实际行情。

当前本地发布历史及这两个包都没有10/19完整历史。10/20盘中HTTP报价属于另一条数据链：接通行情不自动补齐DDB历史，更新代码也不更新历史内容。补齐应增量补到最近完整交易日，保留已发布历史；重导相同包不能增加交易日。已有Wind库也不直接等同这套标准化日线/分钟数据。

数字版当前研究输入固定为年化基差，来自 `numeric_excel.capture` 的annual设置。以下按现有 `native/nonregression.py` 解释，不修改口径：

| 指标 | 数据依赖与更新方式 | 本次现象的解释 |
| --- | --- | --- |
| B04.Q 日换手率 | 完整历史日成交量 / 前一日有效正持仓量 | 最新历史是10/16，显示该日15:00正常；不以盘中累计成交量代替完整日量 |
| B10 五期路径效率 | 同一合约连续6个有效日观测，五期净变化 / 五期绝对变化之和；路径总长0留空 | 最新有效日是10/16，实时价格变化不会改写这条历史指标；补历史后才可能推进日期 |
| B09 活跃度 | 当日日量 / 前20日完整有效日量中位数 | 本机00档及03档为空、01/02有值；新合约历史不足，重下旧日数据不能创造样本 |
| B11 振幅压力 | 年化基差需期货与指数同步分钟观测聚合，含前日收盘的绝对振幅，再除以前20个有效历史振幅的中位数 | 本机同样00/03缺失；既需要足够历史窗口，也需要有效同步分钟，不能只检查日线日期或由两腿日线高低价拼出 |

例如IF2611于9/21上市，在现有发布历史中只有14个交易日（至10/16）；即使补10/19，也不足前20日窗口。03档IF2706于10/19上市，当前包中尚无该合约历史，补一天后也不能满足B09/B11窗口。本地复算B04.Q/B10为12/16有效，B09/B11为8/16有效。这个结果解释本地00/03的缺失，不把用户未指定档位的所有公司缺失都归为同一原因；若公司01/02也缺，需进一步定位具体品种、档位和原始缺失原因。

其他指标也不能一概归因历史：采集区间中枢需要有效的实时采样；ETF指标需要ETF/IOPV；理论成本还需要融资/成本等输入。普通历史包并不承诺提供所有这些来源。

## P1：启动前选择补历史，再验证行情网络

旧本地App源码已实现类似顺序：`native/launch_wizard.py`、`native/history_maintenance.py`、`current.py`。其历史维护进程在停止并退出后才允许进入行情网络探测。新展示版和开发版前端均未发布；公司统一目录也没有该向导，以及 `marketdata/history_maintenance.py`、history_remote/history_backfill等完整历史补齐依赖。不能给公司一条调用这些缺失模块的命令。

建议沿用原数字入口，增加独立Windows启动向导。使用PowerShell WinForms与无界面Python服务，数字Excel无需引入Qt或VBA。移入旧本地已实现的必要历史后台时逐文件核对依赖、差异及回归，不复制App前端，不移植开发机凭据。

| 阶段 | 用户看到的内容 | 执行及失败处理 |
| --- | --- | --- |
| 1 选择历史数据 | 日线/分钟截止日期、最近完整交易日；“检查并补齐”“使用现有数据” | 先只读扫描覆盖和缺口；不能只看最大日期就认定全部标的齐全 |
| 2 可选补齐 | 选择补齐后提示连接历史数据网络；显示范围、进度和结果 | 检查已配置解释器及本机历史授权；缺配置给具体说明及只读入口，不盲目安装、不复制凭据。只补缺口/必要修订，验证后发布，保留旧版本 |
| 3 行情网络 | 历史任务完全退出后提示连接公司行情VPN；“验证并进入”“只读进入” | 有界探测且展示失败原因；不自动切换VPN。补齐失败仍可使用原发布数据。采集与历史下载互斥，取消后等待进程/锁释放 |
| 4 打开看板 | 先打开加载状态，再逐档计算；出现四品种首页 | 网络不可用可只读进入；09:29前、15:01起、休市/未知日历不新接入实时，直接说明使用保存数据，不要求无意义网络切换 |

显式 `-ReadOnlyCache` 继续不创建采集器，也不触发下载。Once/Snapshot/Hidden等自动化参数保持原语义，跳过交互；新交互入口默认行为和退出码需在实施时测试。数字独立配置副本沿用，历史新增版本不能覆盖公司整个data或原Wind库。

更新路径：统一分支普通pull后运行原入口即可使用向导和新首页。历史授权、SDK及网络以公司本机检查为准；缺配置提示并允许使用原数据，不要求为了界面更新重导包。移入的是直接查询、字段转换与历史发布所需后台，路由只含股指/对应指数的日线分钟四个来源，客户端不操作VPN。

## P2：精简首页，完整明细继续保留

首页采用与App相近的IF/IH/IC/IM四卡，选择00—03档，切换只改变展示，不改变后台计算口径。默认主数字为期货、指数、调整基差bp和年化；D/T留在明细。首版评审六指标选每日收敛、B10路径效率、B11振幅压力、分钟中枢、B04.Q换手、B09活跃度；与旧App的六项选择有所不同，优先覆盖用户本次关注项。中枢沿用年化输入，不能误标成bp。完整指标仍可从明细查到。

- 顶部常驻短状态，例如“采集中 · 行情10:30:12 · 历史10/16”。分别使用真实行情源时与历史截止；历史不同步时显示范围/异常，不用全局最新日期掩盖某个品种滞后。
- 短标签采用“活跃度”“换手”“振幅”“路径效率”。完整名称、指标代码、单位、公式、来源、样本条件和缺失原因放明细。历史组注明“历史10/16”；缺失显示空白及“样本不足”“缺分钟”“缺OI”等真实原因，不能仅凭空值猜原因。
- 20日/3月/6月/12月分位与n相邻。保留既有分位和样本口径，合法0仍显示0%；固定合约研究样本与分位池样本分别说明，不混用n。
- 计算中、只读、历史回看、数据延迟、错误、已停止使用短文本状态；“计算完成”“写入/保存时间”“文件路径/运行号”在紧凑运行栏或详情中查阅。保存快照与仍受启动器维护的实例可辨认。
- 现有四张明细表和溯源保留：首页减内容，不删除400行指标。后台写入固定数据区域，选择单元格、筛选、滚动和当前页保持；不每轮重置选择或激活首页。相同数据不重画图、不反复保存。

先选一种小图辅助比较即可。建议使用绑定单元格的原生分位图，或有真实连续样本支持的走势；静态图片可作一次性说明，不代替实时数字。图表和时间戳均不能伪造新行情。暂无必要加入装饰图或大面积色块闪动。

## 独立评审样例与验证

开发机样例位于 `.deps/numeric_ui/outputs/numeric_ui_20261020/Delta1_精简看板评审样例.xlsx`，完全使用明确标注的合成数据，无真实行情，不进入Git。三页为概览、示例明细、启动流程。E3下拉切四档，通过公式驱动卡片及一个原生分位图；“启动流程”页只是流程示意，按钮形状不执行下载或网络切换。样例不是正式400行明细替代品，也不是生产模板。

已用工作簿引擎检查四档选择、空白和合法0，未发现公式错误；三页渲染检查通过。另用本机Excel16.0独立实例只读打开同一成品，切换四档后合约、对应价格、振幅空值/有效值及图表来源均与明细一致，确认3张表、1个原生图表、有效下拉和原始时间说明。测试退出只关闭自己的实例，不修改用户工作簿。证据在 `.deps/numeric_ui/native_review_check.json`。

原样例验证的是布局和公式交互，不是公司验收。本次获批后另对正式模板执行同一可见Excel中的四档切换、图表、缺失/零值、输入变化、源时变化及阅读位置保持测试，另实际走通向导缺DDB配置→现有数据→只读路径。公司DDB真实补齐和新版本实机运行仍待用户测试。

实施后的必要验收：

1. 下载跳过、失败、取消、重复启动及历史任务退出时序；原历史/配置不被覆盖，部分下载不能发布成完整历史；网络阶段互斥。
2. 非接入时段不新联网；原缓存仍显示真实时点；补历史后B04.Q/B10日期推进，样本仍不足时B09/B11保持空白。
3. 实际打开的同一生产工作簿，输入变化后目标卡片和明细更新、源时可见，冻结输入不伪称新行情；四档、空值/0、图表和单位一致。
4. 滚动、选中、筛选、切页、编辑或保存对话框期间的写入与错误状态；计算/写入/保存频率分别控制，无无意义闪动。
5. 公司实机检查已有解释器、历史授权、两种网络与真实窗口；本地合成、开发机有限实连和公司验收分别记录。

App后续仍按展示版看核心与异常、开发版看诊断溯源分工，共用数据源、时段与指标解释。其前端继续只留旧本地目录；本次不提交、不推送。
