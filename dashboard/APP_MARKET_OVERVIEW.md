## 当前时刻与昨日参照

概览独立读取同一份已发布历史版本和同一接收截止时刻的实时SQLite，避免每三秒重复计算整组历史研究指标。四个指数与16个期指之外，持续采集增加上述四只ETF；源端某一标的缺失时，其余有效报价继续显示。历史bar仍只允许指数和期指，ETF只进入明确注册的观测读取契约。

最新价和涨跌优先使用当前HTTP报价与源端 `yesterdayClosePrice`，不要求今日日线已写入。源端昨收缺失时，仅当前日有效报价可以使用**准确上一交易日**的已完成历史收盘；不会把更早收盘冒称昨日。只有历史价格时显示原日期，不伪造实时涨跌。期指涨跌明确为较昨收，不暗换为昨结算。

行情源时间、HTTP接收时刻、页面计算/应用时刻分开。原30秒时效、3秒期现同步规则不变。源日期仍按原接收日推定，没有认证成交易所日期。缓存保留价格及原日期，当前基差/年化/IOPV不使用陈旧或不同步的腿。

期指主价独立有效；辅助基差使用第六版A01，年化是未调整对数基差年化，T<5留空。历史位置复用第六版A02核心的此前20交易日半权分位，当前日排除，固定具体合约，窗口缺日保留空值；不采用旧连续档位分红分位，不修改32项指标公式。

历史目录或合约参考文件暂不可用时，错误单独显示，指数与ETF仍可读取已有实时库；历史依赖项留空，恢复后重新加载同一发布版本，不重置配置。

## IOPV、权重与贡献的取舍

IOPV与折溢价保留在ETF卡片，但必须有明确ETF/IOPV/对应指数映射及同步报价。原配置 `research_etf_iopv_mapping` 可以提供映射；不猜测IOPV代码、不用指数价格或昨日净值替代。2026-10-26获准的四轮真实读测确认四只ETF价格可取，返回字段没有独立IOPV；当前本机也没有相应映射，因此显示待接入。

成分股权重、每只股票和行业贡献适合放在指数详情，不占用主屏行情卡片。本轮核查当前配置未提供有效权重及全成分行情，详情如实说明缺口，没有生成伪贡献或按最新市值反推权重。接入时仍需权重生效日、前收基准、股票行情时间、行业映射和公司认可的贡献定义；当前未承诺这部分已计算。

可在原 `native.json` 中按需追加 `overview_etfs` 列表，每项是 `symbol`、`name`、`root`（IF/IH/IC/IM），不自动写入或覆盖个人配置。IOPV沿用已明确的 `research_etf_iopv_mapping`，额外订阅合计上限100代码。

## 启动无窗口的检查

现有启动器保留隐藏控制台、正常Qt主窗口和分路日志。此次修正预检未接收 `--local-root` 的问题；历史快检错误独立记录，避免被当成缺GUI依赖而在创建主窗口前静默退出。真正缺运行依赖或配置JSON无效仍报告失败，不重置配置。

公司更新后若双击VBS仍无窗口，在**原仓库根目录**运行：

```powershell
git pull --ff-only
.\dashboard\diagnose_presentation.cmd
```

可用 `start_presentation.cmd` 调用同一程序以区分脚本宿主与App失败。诊断只读分支/提交、入口文件、已有启动阶段、脚本宿主启用策略、解释器和依赖；不启动App、不联网、不连接VPN。报告保存在 `dashboard/runtime/app_startup/diagnosis-<日期时间>-<PID>/diagnosis.json` 和同目录 `preflight.json`。若当日没有新的 `run-<PID>`，说明尚未看到PowerShell启动器记录，需要继续检查VBS关联、脚本宿主/执行限制和实际点击路径，不能直接认定为数据或VPN问题。

本机真实PowerShell入口离屏启动检查退出0；本测试沙箱拒绝初始化Windows Script Host，因此不将VBS宿主实启记为通过。公司本次无窗口的根因待该机报告，不能用开发机结果代替。
