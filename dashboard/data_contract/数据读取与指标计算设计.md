# 新下载数据如何进入桌面看板与指标计算

初稿日期：2026-09-30。仅国内 A 股指数与 IF/IH/IC/IM 股指期货。历史数据完全待未来新下载，没有注册已有历史库。

2026-10-01 更新：下文保留设计推导。原生 App 页面、repository 和公式 v2 已实现，实际操作和边界见 [../native/README.md](../native/README.md)；公式窗口采用 `count/unit`，可执行样例见 [formula_inputs.example.json](formula_inputs.example.json)。本版回放使用当前冻结版本的研究历史，任意长历史补算、严格旧知识状态 UI 和供应商下载器仍待后续。

## 一、总体框架

```text
独立下载模块 → 原始证据 + 标准历史 Parquet + 版本目录
现有实时采集模块 → 新采集热库 SQLite + 实时归档
新参考资料下载 → 指数/挂牌合约/日历/映射
                         ↓
历史/实时数据访问层 → 按时刻和频率取数 → 指标调度与缓存 → 因子结果存储
                         ↓
                原生 Windows 桌面 App
             数据源设置 / 看板 / 公式 / 回放
```

下载模块不依赖 dashboard；dashboard 可以调用它的公开入口。历史访问层不启动采集，不直接包含认证信息。前端只提交查询参数和指标声明，由 Python 后台读取和计算，不能把全部秒级历史装进 UI 或公式子进程。

建议继续采用上轮确定的原生 PySide6 + pyqtgraph 方向。后台线程处理 I/O 和计算，UI 线程收到结果再更新图表和卡片。关闭市场后显示最后可用时刻与“休市/源时间待核验”，不能以持续轮询制造假动态。

## 二、当前初版的历史能力为什么不够

`gateway.py` 当前从实时库读取末段记录，每标的只保留约 300 条同合约/同日观测；不是 300 个真实秒 bar。大范围历史接口、按交易日跨日窗口、日分钟秒数据源组合和真实历史回放尚未实现。

`formula_worker.py` 当前接口 `compute(quotes, history, params)` 只有最新报价和单频短历史。均值等窗口按条数计数；重试或停盘后的重复报价可能填满窗口。现有子进程还有限制输入大小的要求，不能直接传全部历史 DataFrame。

因此后续要增加数据访问与输入声明，保留简单公式兼容入口，不在 UI 页面代码中添加任意读取 CSV/Parquet 的逻辑。

## 三、统一读取接口

本轮提供 `BarDataset(root)`：root 完全由调用者指定，无默认外部库。`read_bars(symbols, frequency, start, end, as_of, knowledge_at, fields, version, ...)` 按标的、频率、UTC bar 结束时间、可用时间、修订版本筛选。`fields` 下推到 Parquet 列读取，manifest 范围用于跳过无关分片。

调用范例：

```python
from dashboard.marketdata import BarDataset

ds = BarDataset(user_selected_dataset_root)
bars = ds.read_bars(
    ["IC2610.CFE"], "1m",
    start="2026-09-30T01:30:00Z", end="2026-09-30T03:30:00Z",
    as_of="2026-09-30T03:31:00Z",
    fields=["close", "volume", "quality_flags"],
)
```

该例仅说明格式，不代表此代码已经绑定了目录或有真实数据。新下载完成后在 App 注册 dataset.json，才能计算真实指标。

下一步在此基础上增加 `MarketDataRepository`，注册多个用户选定的数据集，并提供：

- `read_window(input_spec, as_of)`：60 个交易日、120 个有效分钟或 300 秒范围；这三种窗口不互相冒充。
- `resolve_alias(alias, trade_date, knowledge_at)`：读新参考映射，返回实际合约。
- `read_observations(source_id, cursor)`：只增量读取指定的新实时库。
- `capabilities(instrument, frequency)`：报告已有字段、覆盖、单位、源时间精度和缺口。
- `freeze_inputs()`：一次计算绑定固定的历史版本及实时游标，记录可追溯输入。

这些 repository 接口是待实现设计；本轮已落地的是底层 BarDataset 和实时观测桥接，不能把规划接口当作现有可调用函数。

## 四、三个频率各有什么用途

| 数据 | 推荐窗口 | 指标与页面 | 不能替代的内容 |
| --- | --- | --- | --- |
| 日频 | 20/60/120 个已结束交易日 | 正式涨跌幅、日波动、价差历史分布、分位数、基差长期背景 | 当前盘中价格、盘口和精确秒变化 |
| 1m | 30/60/120 个有效 bar 或指定会话范围 | 分钟走势、跨期/期现价差曲线、盘中波动、分时异常 | 真实秒级极值、撮合顺序和历史盘口 |
| 真实 1s | 30/60/300 秒事件时间范围 | 短时变化、价差突变、动态轨迹、短窗波动 | 数据源没提供的五档盘口或逐笔成交 |
| 实时观测 | 最新一笔和明确接收时间窗口 | 当前盘口价差、中间价、两腿可买/可卖价差 | 完整成交 bar、确认的源时钟与精确秒量 |

交易日窗以新下载并核验的日历为准。有效 bar 计数与自然分钟范围都应可选；缺 20 分钟时不能把 120 条稀疏 bar 标成“过去 120 分钟”。

指数若源发布节奏是数秒更新，1s 表可以稀疏，但需要显示真实更新节奏；不得填充价格后计算“每秒波动”。

## 五、公式输入声明

每个公式先声明输入，再编写计算逻辑。示例见 `formula_inputs.example.json`，至少包含：

```text
输入名称 / dataset_id / 具体标的或历史别名 /
频率或 observation 类型 / 所需字段 /
窗口及暖启动长度 / 已完成数据要求 / 对齐与缺失规则
```

后台根据声明读取最少字段和最小范围，形成有界输入数组。简单模板沿用 `compute(quotes,history,params)`；多频模板计划为 `compute(inputs,params)`，如 inputs['spot_daily']、inputs['near_minutes']，不允许公式自行浏览磁盘路径。执行器扩展后才支持此接口。

一条组合指标可同时读取 60 日日频、120 条分钟、300 秒秒级和当前报价。上下文统一 `as_of`，只纳入已经结束且可用的历史数据；当前实时报价作为独立 input，不覆盖正式日收盘。

若需要 pandas/vectorized 复杂计算，后续单独做受控的专业模板执行入口与资源限制。当前受限 worker 不支持随意 import pandas、文件读取或完整 DataFrame API。

## 六、指标优化顺序

1. **正式日涨跌幅**：最新价相对已核验前收盘，而不是相对采集开始首笔。只有期货结算价时明确显示“相对前结算”。
2. **盘口与跨期可成交区间**：中间价差、买入价差 `ask_near-bid_far`、卖出价差 `bid_near-ask_far` 同时显示。字段缺失或两腿接收时刻偏差过大时不给有效信号。
3. **期现基差**：指数与对应实际期货对齐后计算点数与 bp；年化需明确剩余天数口径、到期日、除数和单位。未加入分红/资金成本时不能宣称为净套利收益。
4. **跨期 Z 值/分位数**：基于真实历史，而不是重试次数。具体合约换月时重置或按声明的拼接/DTE 分组；不能把远近月关系变化当作简单异常。
5. **分时波动与短时突变**：仅在频率和覆盖足够时计算。午休、跨日、停盘缓存不纳入连续收益序列；窗口不足显示 warmup。
6. **成交量异常**：单位与完整区间已核验后，比较同一品种同一时段的历史分布。指数汇总量与期货手数分开。当前轮询增量不参与真实分钟量比。

闭市保留最后一次计算及时间，指标不更新到未来交易日。接收时钟一致只证明采样接近，不能证明交易所源事件同步；当前源缺日期时在卡片上明确标注。

## 七、历史和实时怎样衔接

启动时先按 formula input 读足历史暖启动数据，再增量读取新实时库。只接入用户新选择的目录，不自动扫描或补接其他市场资料。

同一时段的官方历史 bar、真实逐笔派生 bar和轮询观测是不同来源：分别存储，明确选择，不叠加 volume。未来官方完整分钟数据到达时可替换展示中尚未完成的派生分钟，但须保留来源/版本和修订痕迹。

只有已经核验源事件时间、成交量区间和会话后，才能从实时源构造标准成交 bar。否则实时生成的只是接收时间采样曲线，在 UI 单独标明。

跨期两腿优先同一 event_time 的 inner join；如采用最近一次可用值，必须设最大时差，不跨会话、交易日或合约换月前向填充。日频背景只使用截至 as_of 已发布的完成日，盘中当日累计不能冒充正式日频。

## 八、增量计算与结果保存

增量下载的检查点和增量计算的检查点要分开。

因子状态计划按 `公式ID+公式版本+输入声明+实际合约组合` 保存，记录输入 dataset/version、实时 source/cursor、最后计算时刻和必要的滚动窗口状态。新 bar 到达时仅计算新增范围。

迟到数据或历史修订时，从受影响输入时间重新计算。有限窗口指标需连带重算后续窗口受影响的输出；EMA 等递归状态需回到可信状态点继续重放，不能只重算修订所在一行。结果写新修订并保留原输入版本。

因子结果继续由 dashboard 自己保存，目录由 App 单独选择。每行应记录 event_time、calculated_at、公式版本、输出、质量状态、输入版本/游标与实际合约。旧初版已有公式版本与结果 Parquet 机制，跨频率检查点和受修订范围追踪待扩展。

## 九、App 需要增加的内容

数据设置页：添加历史数据集目录、指定新实时采集目录、参考资料目录、结果目录；扫描只读取 dataset/current/manifest；显示代码/频率/字段覆盖和最新时刻，验证通过后启用。

公式页：日频/分钟/秒/实时输入选择器、窗口单位、字段、合约换月规则、缺失与对齐策略、试算预览。缺数据时显示具体缺哪一源/频率/字段及所需下载范围。

看板：顶部最新报价与关键价差卡片；中部分钟价差/基差曲线及历史分位区间；秒级曲线独立标示来源精度。提供 1d/1m/1s 切换、时间范围、缩放、十字光标、暂停实时/恢复和截至时刻。图表按视窗下采样，原始指标仍在后台全精度计算。

历史回放：固定数据版本和 as_of，按时间逐步推进；标明“修订后研究历史”或“已入库知识截止”。没有真实 available_at/recorded_at 证据时不能把前一种标成后一种。

## 十、当前实时下载数据满足什么格式

本判断来自采集代码和新建临时合成响应测试，不将任何已有实盘库绑定到新看板。

| 项目 | 当前实际情况 | 结论与下一步 |
| --- | --- | --- |
| 增量持久化 | SQLite sequence，事务写入，Parquet 不可变分片及注册清单 | 具备基础，可按源库游标增量读取 |
| 标的身份 | symbol、source_symbol、mapping_date、trading_date | 能保留 alias/实际合约；需要独立新历史映射参考表 |
| 接收时刻 | SQLite received_at 完整时间；timestamp 为 UTC 接收整秒 | 桥接可保留精度；不能将 timestamp 当源事件时间 |
| 源时刻 | quote_time 为 HH:MM:SS，无交易所报告日期 | source_event_time 应为空并标为待核验，不能猜成已证实 |
| 交易日 | 本地规则/日历推定 | 不是交易所报告值，停盘缓存仍需独立会话核验 |
| 价格与盘口 | 最新价 close + 买卖 1–5 档价/量 | 可算抽样盘口与价差；指数没有盘口时留缺失 |
| 成交量 | volume_total 累计源量；volume 为连续采集差值，含实际接收间隔 | 属 observation interval，不能直接作为标准 1s/1m volume |
| 首笔/重启/间隙 | 增量为空并打标 | 符合不伪造缺失量的要求 |
| 正式 OHLC/前收/金额/持仓 | 当前规范表未全部保留；部分字段可能在原始 HTTP 响应中 | 将来核验源含义后扩展，不能假定历史已满足 |
| 旧 Parquet 精度 | schema swhy_realtime_v3；timestamp 是整秒，未包含完整 received_at/run_id/poll/batch | 要升级归档 schema 以独立恢复精确观测身份；当前桥接依赖热库 |
| 单位/可用时间 | 原始源单位未认证；缺完整源日期及历史 available_at | 不直接满足标准成交 bar 或严格当时可知回放 |

所以当前实时数据**适合作为实时观测输入，经过桥接后可读取；不直接满足新历史 bar 规范**。不能单靠改后缀或列名转换。

下一步采集模块可增加 `dataset_id/instance_id`、完整 received_at、稳定 observation_id、source_event_time 可空、时间/单位认证状态、经核验的 prev_close/settlement/OI/turnover 等可选字段，并写入新归档 schema。当前模块的原始证据保存与缺失量规则可复用。

实时 cursor 必须与数据源 ID、数据库实例绑定；换库/清空库时重置 cursor。当前代码无永久数据库实例 UUID，本轮桥接文档已明确这一限制。

## 十一、实施次序与验收

1. **已做数据规范基础**：本轮数据 schema、参考读写、合成样例与测试；不需要先下载大历史。
2. **新数据小样本下载**：四个指数 + 一个股指品种的两个具体合约，先约 20 个交易日日频、1–2 日分钟、有权限才补真实秒级。所有来源、单位和可用时间先验收。
3. **原生 App 数据源页与 repository**：用户选择新目录，验证能力；异步取数；不绑定任何既有市场库。
4. **指标 v2 与图表**：先完成日涨跌、可成交跨期价差、期现基差、分钟曲线；再加入历史 Z 值/分位和秒级突变。
5. **断点续算与回放**：与下载增量分开保存，验证停机恢复、补洞/修订、换月和版本复现；缺源可用时间则保留限制标记。

本轮提供的小型 store 是验证交接协议的参考实现，尚未做大规模碎片压缩、全历史性能测压或与原生 App 的集成。实际下载完成后再做针对真实规模的扫描索引、分片大小与缓存优化。
