## 打开与刷新

- 日常自动更新：双击本dashboard文件夹的 `start_numeric_excel.cmd`，打开说明在同目录 [打开方式.md](打开方式.md)。未显式指定Python时优先选择公司已有swhy_delta1环境，无需激活Conda或设置变量；也可为脚本建立桌面快捷方式。根目录重复的公司入口已移除。先选择“检查并补齐”或“使用现有数据”；补齐可选“自动连接并补齐”或“已手动连接，开始补齐”。自动模式先复用已通DDB网络，有实际历史缺口且网络不通时才使用本机VPN配置登录。历史进程退出后提示手动切回实时行情VPN，验证成功再打开Excel；失败可只读进入，时段外跳过实时接入。
- 只跟随本地缓存，不创建采集器：`dashboard/start_numeric_excel.cmd -ReadOnlyCache`。
- 已手动完成准备、需要跳过向导：`dashboard/start_numeric_excel.cmd -NoPrompt`，仍受时段守卫与连接验证。Once/Hidden/Snapshot/外部Feed也不弹向导。
- 一次性生成当前本地结果：`dashboard/export_numeric.cmd`。
- 从已有快照生成：`dashboard/export_numeric.cmd "快照.json" "新的输出.xlsx"`。已有目标文件拒绝覆盖。
- 自选保存位置：`dashboard/start_numeric_excel.cmd -Output "新的输出.xlsx"`。

启动器打开独立 Excel 实例，结果变化后更新同一个已打开工作簿的单元格并保存；相同结果仅每约30秒更新状态和保存。计算目标间隔3秒；一次计算超时则顺延，不堆积并发请求。首次加载日线和分钟指标较慢，有匹配数据配置标识的每日计算缓存时先展示上次结果，并明确标为待本轮核验；未标识/另一配置的旧缓存保留但不直接复用。关闭该 Excel 窗口后停止本次采集和数据服务，不操作用户原有工作簿。直接双击保存的 `.xlsx` 只查看最后保存结果，需要启动器才能自动更新。

首次无每日缓存时，现在先打开 Excel，依次计算并填入 00/01/02/03 四档，窗口顶部显示进度与累计用时。空白表示尚未计算，部分结果不会写成完整每日缓存；`-Once` 也会等四档全部完成。`-ReadOnlyCache` 只禁止新增采集，仍需从本地日线/分钟数据计算指标，不等于直接打开已有工作簿。前端 App 先显示窗口且只请求当前档位，因此不能用“前端已打开”判断数字版全部四档已经算完。

终端会显示实际 Python 与本次日志目录 `dashboard/runtime/numeric_live/<运行号>/`。`producer.out.log` 记录各档完成时间，`workbook.status.json` 保存当前阶段，失败时终端直接附上 `producer.err.log` 的末尾内容。首次完整计算超过600秒仍会停止并保留日志。2026-10-19 已修正 UTC 时间逐行转换反复探测可选依赖及 pandas 重复复制大份元数据造成的开销，无需另装 pytz；数据计算口径保持一致。

默认成品保存在 `data/cache/dashboard/numeric/数字看板_日期_时间.xlsx`，每日计算缓存为 `data/cache/dashboard/numeric/YYYY-MM-DD/latest.json`。原始保存行情继续使用配置的 `realtime_root/live/quotes.sqlite3`。这些数据都不进入 Git。

2026-10-20 补充启动状态：终端依次提示“完整计算结果已就绪”和“Excel 首次写入成功”，后者附实际文件路径。仅第一条不能证明 Excel 已写入；成功保存后才提示持续刷新，此后每约30秒有成功刷新提示。首次计算同一阶段每约10秒重报累计耗时。旧版可能最后停留在“计算02”，因为03较快且完成后未打印；可用本次 `workbook.json` 的 `ready=true` 和数字看板16行确认四档计算已完成，仍需另外确认 Excel 写入。启动器自动打开的独立 Excel 窗口用于持续查看；直接打开保存文件仅查看快照。

若旧版持续报告保存成功却无窗口，原因可能是 Excel 忽略了工作簿打开前设置的可见状态。本次修复将显示操作移到打开工作簿之后，恢复该工作簿窗口并最大化，检查后打印“Excel 窗口已显示”。在原启动终端按 Ctrl+C，等待返回命令行，再 `git pull --ff-only` 并重新运行启动命令；不结束其他 Excel 进程，不需重导数据。显式 `-Hidden` 仅用于隐藏测试/导出，不显示窗口。

## 内容和时点

日常显示四页：概览、指标、组合对比、来源与状态。概览为四品种卡片，E3选择00—03档，显示行情、六项指标、四窗口分位/n和原生分位图。每卡分别标行情时点、数据类型及所展示历史指标的最早日期。指标页有独立E3档位选择，25项指标按四品种并排显示数值、日期和短状态；每项仍用自己的实际时点。组合页的黄色格可编辑类型、具体合约、输入及时点，分类明细分列盘中/日终。

原数字看板、分位与样本、研究指标和辅助表均保留，默认隐藏；需要完整公式/缺失原因时，右键工作表标签→取消隐藏→研究指标。原研究数据未删除，盘中扩展使行数不再固定400。跨期、跨指数通过组合页调用同一研究模块。“样本/分母”对应历史不足、输入缺失或分母无效组合原因，不凭空断言只缺样本。

概览底部显示运行号、文件名、维护状态，以及计算/写入/上次成功保存时间；Excel底部状态栏在Save返回后显示本次保存成功时间。退出显示“已停止”。刷新不切换工作表，不重设用户档位、选中单元格和滚动位置；编辑期间COM拒绝调用则保留运行并重试。

## 可选历史补齐

尚未配置DDB时选择“使用现有数据”，不影响界面或HTTP行情测试。首次本机配置执行 `dashboard/configure_numeric_history.cmd`，按提示填数据库地址、端口、账号、密码、SSL及已有DDB Python路径。输错后可重跑该入口更正，保留VPN配置和历史路径；重开数字Excel再补齐。

VPN另用 `dashboard/configure_numeric_vpn.cmd` 配置网关、已核验的证书SHA256指纹、VPN账号密码；已有加密配置可通过 `--reuse-config` 和 `--trust-file` 引用，不改写旧文件。自动登录复用已安装的深信服客户端与PowerShell 7，缺少依赖/需要验证码或二次认证时提示手动登录后重试，不自动安装或反复尝试密码。DDB与VPN密码均用当前Windows用户DPAPI加密，仅保存在本机忽略目录；不能把另一台电脑的加密文件直接当作公司凭据。

取消或超时会先结束本次登录辅助进程和历史进程，再进入下一步。**任务退出不等于VPN已断开**：不自动登出DDB VPN、不自动登录行情VPN，不停止其他客户端；用户按提示手动切回。时段外补齐结束也会显示该提醒，随后只读打开。使用现有数据、ReadOnlyCache或历史已完整不会触发VPN自动登录。

补齐只到上一交易日，按具体合约上市/到期范围检查日线和分钟缺口。原有效行情保留，新增分片验证后发布；来源冲突保留原值并说明。单次启动有轮次/查询预算，结果若仍提示缺口，不算全部完成，可下次重试。取消等待历史进程退出后才允许进入下一网络阶段。历史完整也不保证新上市合约已有20期样本或成本/ETF等额外输入。

实时可计算项随有效行情更新；需要完整日线、分钟线或历史 OI 的指标只随对应数据更新。每行标出具体合约、单位、数据类型、实际数据时点及缺失原因。分位的 0% 是合法数值，不改成缺失。数字看板年化和分位使用 Excel 百分比格式；研究指标按相邻单位保留原数值（% 表示百分点）。

北京时间交易日 **09:29（含）至15:01（不含）**允许新行情接入。09:29前、15:01起、周末/已知节假日、未核验日历年份均只读本地数据；时段判断不联网更新日历。午间按现有新鲜度规则显示带时间的缓存，不伪装为连续交易报价。正在进行的有限请求允许完成，时段结束后不发新行情请求。

展示取值顺序：有效同步实时行情；否则比较最近完整历史收盘和最后一组有效同步保存观测，显示较新者。较晚到达的陈旧/不同步轮询不能覆盖最后有效状态。保存行情回看保留原始源时/接收时/自然日 T，并明确 **不保证就是最终收盘价**。没有有效保存观测时使用最新可用历史 F/S/D/T；新挂牌合约若只能回看历史档位，显示实际历史合约，另列当前挂牌合约，禁止张冠李戴。历史分位仍使用原连续档位固定分红情景，不冒充真实逐日分红。

## 发布隔离与验证

用户最新授权是推送数字 Excel 及必要公共后台，暂不推新看板前端。提交仅包括数字服务/启动器/无业务数据的空白模板、时段守卫、必要测试和文档。真实 Excel 成品、历史、行情库、诊断快照、凭据及其他任务修改仍留本地。空白模板是唯一允许进入本次 Git 的 `.xlsx`，发布检查确认没有行情行、外部链接、宏或凭据。

自动验证包括时段边界/休市日不联网、缓存同步与陈旧排除、历史 T 按原日期计算、合法0与空值区别、实际 Excel 同一工作簿连续更新。2026-10-20另经用户授权进行本机VPN人工实连：三轮各20个标的，独立缓存、同一可见Excel的价格和源时变化与feed相符，停止采样后相同缓存不声称新行情，原行情库不变。它与自动合成测试分开，细节见刷新诊断说明；公司那份窗口和长期盘中运行仍需现场验收。
