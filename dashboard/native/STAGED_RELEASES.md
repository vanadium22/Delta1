## 一次更新、分阶段生成

先修改共享页面、主题或计算，再运行 `dashboard/build_releases.cmd`，或在开发工作台「数据与任务」
点击「生成全部阶段稿」。构建器使用当前公式定义重新计算合成数据；四个交付共享同一快照。
新指标进入哪些阶段，由 `release_profiles.py` 中的范围决定，较早阶段不会自动升级为完整功能。
20% / 50% / 80% 是内部的展示范围标签，不作为工时或历史研发进度记录。

| 内部阶段 | 交付名 | 页面与能力 | 数据 |
| --- | --- | --- | --- |
| 20% | 指标样稿 | Excel 三张表：市场概览、样例数据、指标口径；原生四曲线图 | 分钟；基础期现/跨期；输入修改后重算 |
| 50% | 桌面原型 | 单页概览；四品种基础矩阵和比较图；手动刷新 | 分钟；无回归、自定义、事件与详情 |
| 80% | 联调稿 | 三页；回归、自定义结果、基础异动列表；手动刷新 | 日、分钟；不带秒级与详情数据 |
| 1.0 | 1.0 | 三页完整交互；期限结构、单品种与事件详情；自动刷新 | 日、分钟、秒 |

共同指标保持相同口径。ETF 尚未接入，合成示例持续保留明确标记。
Excel 是导出时点的快照；可编辑输入、表内公式和图表联动，行情变化需重新导出。

## 交付位置与历史

每批位于 `dashboard/outputs/01a0f78e-6886-76a2-83d9-970f6893b518/<时间>/`。
`latest.json` 只在整批完成后更新；旧批次不会覆盖。
每个桌面交付目录包含 Git bundle、源码 ZIP 和页面截图。Python 与安装说明包含在公开仓库中。
接收方可执行 `git clone "Delta1-market-dashboard.bundle" Delta1`，再按 README 安装依赖、启动演示。
源码 ZIP 不含 Git 历史。不要把本项目、整批父目录或内部清单一并发出。

三个可持续更新的独立仓库分别位于 `dashboard/runtime/distribution/` 下的：

- `Delta1-market-prototype`
- `Delta1-market-integration`
- `Delta1-market-dashboard`

构建时移除不属于该阶段的类、详情方法、频率、快照字段和无用配置常量。
公开仓库不携带内部构建配方、开发管理页面或父项目 Git 历史。
构建器拒绝覆盖手工修改过的公开仓库，也拒绝在已有较高阶段的仓库中生成较低阶段。
后续始终修改共享源；不要直接修改上述导出仓库。

## 命令与故障恢复

```powershell
python dashboard/build_stage_releases.py
python dashboard/build_stage_releases.py --resume "完整的未完成批次路径"
```

恢复使用同一输入快照；已完成批次不可恢复覆盖。Excel 输入与构建器校验一致时复用已验证工作簿，
其余未完成输出从当前源码重新生成。`release_manifest.json` 记录数据摘要和各阶段构建标识。

Excel 依赖 Codex 附带的 Artifact Tool Node 运行时；默认从当前用户缓存查找。
位置改变时设置 `DELTA1_ARTIFACT_DEPENDENCIES` 为包含 `node/bin/node.exe` 和 `node/node_modules` 的目录。
Python 使用 `SWHY_DELTA1_PYTHON` 或本项目现有环境；无需重装 Excel。

## 验证

工作簿导出会重算，并与同快照 Python 指标对照；测试输入修改和清空，再恢复原值。
桌面交付从公开源码直接启动并截取每页；测试覆盖 bundle 克隆、功能裁剪与公共历史隔离。
交易轴统一折叠午休及隔夜，保留盘中缺口、真实悬停时刻和会话断线。
