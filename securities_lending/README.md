# Delta1 券源工作台 · 原生桌面 App

Python + PySide6 原生 Windows 应用，默认入口为 python -m securities_lending。界面按公司 1920×1080 屏幕设计，支持 Windows 放大显示、小窗口横向滚动和可收起的券源明细。默认启动不打开浏览器。

## 日常启动和查询

1. 在 swhy_delta1 环境中双击 securities_lending/start.cmd；家中使用 start_demo.cmd。环境说明见 [COMPANY_SETUP.md](COMPANY_SETUP.md)。
2. 首次打开「设置 → 券单来源」，选择公司的「发送券单」根目录。
3. 每次正式启动按**北京时间运行日期**读取「根目录 / YYYY-MM-DD / 申万内部券单YYYY-MM-DD.xlsx」。**先复制到项目本地并校验，再读取本地副本的“库存券单”Sheet**。
4. 输入代码或名称，按 Enter 查询库存与 Wind 本次最新价。多个标的可用空格、逗号、分号分隔；名称支持包含匹配，结果按完整证券代码去重。
5. 在黄色输入框为每只股票填写**目标名本（万元）**，点击「刷新价格并计算」或按 Ctrl+Enter。修改金额后，旧计算立即失效，必须重新计算才能复制/导出。
6. 「打开本地数据」打开当前成功下载或正在使用的缓存批次目录；尚无成功文件时打开本模式数据目录。「文件与同步详情」持续提供实际文件名、共享来源、本地路径、下载/检查时间、大小与 SHA256。

仓库根目录命令：

~~~powershell
python -s -X utf8 -m securities_lending
python -s -X utf8 -m securities_lending --demo
~~~

演示模式始终使用合成券单与价格，不访问公司共享盘、不调用 Wind，窗口有固定演示标识。演示设置独立保存到 data/demo/config.local.json，即使正式配置损坏也可启动演示。正式/演示缓存和导出模式均有区分。

## 已确认的默认业务口径

默认列名依据用户提供的申万库存券单结构，匹配列名而非固定字母位置。所有列名都可在「设置 → 列名映射」逐项修改。

| 用途 | 默认 Excel 列名 | 处理 |
| --- | --- | --- |
| 代码 / 名称 | 证券代码 / 证券简称 | 支持沪深北代码、前导零和交易所后缀 |
| 可融股数 | 可融股数 | 默认与实际可融股数逐笔比较 |
| 实际股数 | 实际可融股数 | 两列取较小值，保留各自原值 |
| 费率 | 参考费率 | 普通数值 0.05 显示 5%，不假定年化 |
| 期限 / 来源 | 期限 / 来源 | 每笔分别保留 |
| 原始市值 / 上限 | 可融市值 / 可融市值上限 | 仅作追溯参考，不参与当前估值和需求换算 |
| 券单价格 | 收盘价 | 参考字段，不替代 Wind 最新价 |
| 行业 | 自动识别 | 缺失时由 Wind 补充，默认申万一级 |

~~~text
单笔有效库存 = min(实际可融股数, 可融股数)
标的有效库存 = 同一证券各笔有效库存之和
最大可借股数 = floor(标的有效库存 / 100) × 100
库存市值（元） = 标的有效库存 × Wind 本次有效最新价
需求股数 = floor(目标名本（万元）× 10000 / 最新价 / 100) × 100
取整名本 = 需求股数 × 最新价
未用名本 = 目标名本（元）− 取整名本
~~~

- 从 Excel 数量/金额解析、单位换算到汇总和取整均使用 Decimal，0.57 万股准确转换为 5700 股。
- **先逐笔取小值再汇总**，不能改成两列分别合计后取小值。主表显示有效库存、整百股上限以及两列原始合计，展开明细可查看每笔原值。
- 任一笔必要数量列缺失/无效，汇总仅显示已知数量并标记“已知”，不确认整个标的的可借上限或完整库存市值。
- 超过库存时显示“库存不足”、需求股数和上限，不静默缩减后显示成功。
- **库存市值（按最新价）**、**输入的目标名本**和**券单原始市值（仅参考）**是不同字段。没有本次有效价格时，估值和换算不可用；不得用旧行情或券单收盘价替代。
- 同一标的多笔券源显示费率范围，各笔费率、期限、来源不合并成平均费率。
- 可以在设置中切换“仅使用可融数量列”，适配单列库存模板；默认仍采用两列较小值。
- 单元格显式单位优先于表头，表头优先于设置。支持股/万股、元/万元/亿元。百分比格式与带百分号文本自动识别；普通数字默认小数费率口径，其他模板可切换。
- 原始券单市值只供参考。旧模板缺少原始名本但有券单价格时，参考明细可保留明确标记的券单估算值，不作为主表最新估值。

## 批量输入、编辑和复制

「批量粘贴…」（Ctrl+B）支持一列代码/名称，也支持从 Excel 复制两列：**代码/名称 + 目标名本（万元）**。两列使用制表符分隔，可带“证券代码”“目标名本（万元）”表头；每次最多 100 项输入。

第二列为空时保留已填金额。带金额的名称必须唯一匹配，未匹配或匹配多只时提示改用完整代码；多个输入指向同一股票但金额冲突时，整批拒绝应用。

在表格名本输入框内还可粘贴一列金额，从当前行向下填写；存在无效金额或超出表尾时整列不应用。

| 操作 | 快捷键 |
| --- | --- |
| 聚焦查询框 | Ctrl+L |
| 查询 | 查询框 Enter |
| 下一只股票 | 名本框 Tab / Enter / ↓ |
| 上一只股票 | 名本框 Shift+Tab / ↑ |
| 重新获取价格并计算 | Ctrl+Enter |
| 多选表格行 | Ctrl / Shift + 点击 |
| 选择全部表格行 | 表格 Ctrl+A |
| 复制所选行，含表头、单位、状态和来源 | 表格 Ctrl+C |
| 导出 | Ctrl+E |
| 同步当日券单 | F5 |

输入框内 Ctrl+C 仍复制选中文字。点击名本框时，当前股票与明细同步。「券源明细」可展开/收起，列宽可拖动调整，窄窗口用水平滚动条查看其余列。

## 导出与来源追溯

默认导出 Excel，包含“查询汇总”“券源明细”“数据说明”；也支持 CSV 汇总或 CSV 券源明细。CSV 使用 UTF-8 BOM，复制内容使用制表符分隔。

导出包含：正式/演示模式、库存日期和状态、下载时间、本次价格和来源/时间、目标名本、需求、整百股上限、校验通过股数、取整名本和余量、最新库存市值、两列原始股数、原始券单市值/上限，以及逐笔费率、期限、来源、文件名、Excel 行号、本地快照和 SHA256。

CSV 汇总也有逐笔追溯文本。金额/原始数量保留精确值，Excel 超出可精确表示范围的数值用文本保存。库存不足时“校验通过股数”为空。原生保存对话框可另选位置，默认在项目 data/exports；导出在后台完成，先写临时文件，成功后才替换目标，失败不损坏已有导出。

## 可配置接口与文件同步

「设置」分为四页：

- **券单来源**：共享根目录、文件名模板/通配符、最新一份/合并独立券源、Sheet 名。文件名中的 {date} 替换为北京时间运行日。粘贴带日期目录时自动替换末尾日期。
- **Wind 与环境**：开关、独立 Wind Python 路径、行业字段、参数、口径名称、总超时。
- **表头与口径**：表头行（0 为扫描前 50 行）、两列取小值/单列模式、数量/金额默认单位、数字费率口径。
- **列名映射**：代码、名称、两列股数、原始市值及上限、费率、行业、券单价格、期限、来源。填写完整原始列名；留空自动识别，有歧义则报错。

默认精确匹配“申万内部券单{date}.xlsx”，不因目录中其他文件修改时间较新而误读。找不到文件时提示准确日期和文件名；不自动找上个交易日。

兼容 .xlsx/.xlsm/.xls，忽略 Excel 锁文件。独立券源可显式改用通配符和合并模式；仅去除 SHA256 完全一致文件，其他行累计，不能把同一库存不同版本当作独立券源。

每次成功下载保留新批次，复制过程中源文件变化则中止。全部下载和解析成功后才切换快照。失败仅回退**同日、同来源、同文件筛选和选择方式**的已校验缓存，界面说明“使用当日缓存”及原下载时间，不使用昨日券单冒充今日数据。跨日清空旧结果并同步；每次查询也检查日期。

下载、解析、Wind 调用和导出均在后台执行，底部显示阶段，失败可重试。共享盘 I/O 返回时间受 Windows 管理，等待期间窗口可以重绘；关闭窗口会等待当前后台任务完成。Wind 子进程默认总超时 25 秒。

旧配置升级在内存完成，启动不覆盖本机文件：旧默认“*.xls* + latest”迁移到指定日期文件；原来未设置列映射时采用本版默认列名和小数费率口径；自定义列映射保留。保存设置后写入版本 2 配置。

## Wind 与环境边界

最新价使用 WSQ / RT_LAST，每次查询或计算重新请求，不缓存复用价格；行业默认 WSS / industry_sw，参数 tradeDate={date};industryType=1，按日期和字段参数缓存。

Wind 状态只表示本次请求结果，不代表持续连接。各行显示本机获取时间，明细和导出显示 Wind 返回时间；盘后/停牌 RT_LAST 可能是最近成交价，不保证为逐笔成交时间。行业请求返回错误时保留已返回价格；整个子进程超时则本次行情不可用。

公司建议 App 环境：D:\conda\envs\swhy_delta1\python.exe。现有 Python 3.13、PySide6-Essentials、openpyxl、xlrd 配置保留，本次没有新增依赖。WindPy 由用户在公司自行管理，不属于公共 pip 依赖。可以配置独立 Wind Python，该环境无需安装 PySide6。

公司 Conda 环境是否成功创建、真实共享盘访问、Wind 权限及 Python 3.13 兼容性仍需公司验证。诊断默认不连接 Wind：

~~~powershell
python -s -X utf8 -m securities_lending.diagnose
~~~

## 本地文件与 Git 同步

~~~text
securities_lending/
  config.example.json                 # 可提交模板
  config.local.json                   # 正式本机配置，忽略
  python.local.txt                     # 本机解释器路径，忽略
  data/
    live/YYYY-MM-DD/snapshots/<ID>/    # 本地正式券单
    live/YYYY-MM-DD/latest.json       # 最后成功批次
    live/YYYY-MM-DD/industries.json   # 行业缓存
    demo/config.local.json            # 独立演示设置
    demo/                             # 演示快照
    demo_source/                      # 合成演示源
    exports/                          # 默认导出
~~~

真实券单、缓存、导出、本机配置均不提交 Git。旧网页代码保留兼容，但默认原生 App 不启动它。仓库根 README 的指数工具说明属于另一个模块。

家中修改需要先提交并推送，公司的 git pull 才能取得更新。公司在**实际仓库根目录**检查本地改动后：

~~~powershell
git status
git fetch origin
git switch codex/securities-lending
git pull --ff-only origin codex/securities-lending
~~~

分支尚不存在时使用 git switch --track origin/codex/securities-lending。有本地改动时先保留并检查，不用 reset/clean 强行覆盖；目录叫 dashboard 不影响原生应用入口。
