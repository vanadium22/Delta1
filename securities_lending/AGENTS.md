# 券单 App 后续修改约定

适用于本目录及子目录。用户已明确要求以下持续工作方式：

1. 开始修改前读取 `PROJECT_HANDOFF.md` 和 `README.md`，核对实际 Git 分支、最新提交及未提交改动；不回退或覆盖其他工作。
2. 保持 Python + PySide6 原生桌面方案，遵守交接文档中的已确认业务口径。普通界面细节自行合理决定，只有影响业务正确性的歧义才提问。
3. **每次修改券单 App 后都同步更新 `PROJECT_HANDOFF.md`**，记录行为变化、实际验证结果及剩余验证事项；必要时同时维护使用和环境说明。
4. 完成适当测试和界面检查后，**将本次代码、测试及说明一起提交并推送到开发分支 `codex/securities-lending`，再将本次已验证提交汇总、验证并推送到公司分支 `codex/company-apps`**。这是用户的持续授权，无需每次重复询问是否提交推送；用户后续明确要求暂不提交/推送时从其要求。隔离未提交或无关改动，保留公司分支内其他模块。
5. 仅按明确文件清单暂存本模块的相关改动。不要提交真实券单、缓存、导出、本机配置或其他模块改动；不使用 `git add .`、强推、reset/clean 来覆盖工作。
6. 若无法完成验证或推送，如实说明已完成部分和具体阻碍，不声称成功。公司共享盘和真实 Wind 的结果必须与家中演示/模拟测试区分。

7. **公司日常始终停留在 `codex/company-apps`，仓库根目录一次 `git pull --ff-only` 更新全部已发布模块。** 不再给用户切换到券单开发分支的公司运行命令；切换分支会影响整个仓库，可能使基差源码退出当前检出。交付前核验远端公司分支已包含本次提交，报告公司分支提交号。README、COMPANY_SETUP 和交接提示词保持一致。

启动优先复用通过校验的**当日本地券单**，无可用副本时才同步下载；F5/同步按钮保留强制下载能力。复用库存文件不等于复用 Wind 最新价。
