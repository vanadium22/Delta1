# 个人微信候选：实机验证与安全审查

验证日期：2026-10-15。用户授权测试本人已登录的测试号及指定测试群，目标是**自动找到目标群、识别真正的 @ 本人、读取前后文、发送指定消息**；验证可行后再接入券单。本次仅交付验证记录，券单运行代码、依赖和业务口径未变。

## 当前结论

**本地 OCR 的基本找群、读文本和单条发送已实测可行；还没有通过完整验收、可直接接入券单的插件。** pyweixin 与 wxauto 社区版的 UIA 连接在本机失败。独立试验脚本避开原 OCR 项目的错误发送实现，已从其他会话自动搜索并打开指定群，读到约定的三条前文/真正 @/后文，发送一条测试文本并获用户手机端收件确认。

本次测试微信为 **4.1.15.13**，Python **3.13.9**，不代表公司环境。早一轮因用户临时有事暂停；用户恢复配合后，于 2026-10-15 22:28–22:36 完成本页新增实测。**累计真实发送尝试为 1，未启动常驻监听、未读取聊天数据库或提取密钥、未修改微信进程内存。**

真正 @ 和普通粘贴的同样文字，正文 OCR 与鼠标光标表现相同；**不能据此逐条判定真正 @**。切开目标群后，真正 @ 出现原生红色“[有人@我]”，打开群后提示清除；再切开并发送普通 @ 文字，仅出现未读数，没有该提示。当前证据支持“群级未读提及提示”，不支持历史消息逐条 @ 标记。后续优先继续本地 OCR 适配，但先解决证据关联、漏读与持续采集，暂不接入券单自动处理。

### 视觉后端的离线缺陷复现

用合成群名和文本，将鼠标、键盘、剪贴板全部替换为测试桩，实际调用固定版实现，复现：

1. `send_text(chat, text)` 没有调用目标群切换；参数 `chat` 不决定发送目标。
2. `_foreground()` 返回 False 时，仍尝试按 Enter 并返回 True。
3. `resolve_chat_coord()` 以双向前缀匹配群名，将“测试群”当作“测试群生产”的候选坐标。

这三项是确定的行为缺陷，不是网络恶意代码判定。测试没有操作真实鼠标/键盘或发送消息。初次测试脚本把预期 False 的字段放进 `all()` 导致断言失败，修正为正确的预期语义后复现通过，没有修改上游实现去迎合结果。

- 测试 venv 复用本机基础 Python 包（`--system-site-packages`）；它隔离本次新增依赖，**不是操作系统安全沙箱**。券单正式 Python 环境没有安装这些候选。

## 接入前的剩余验证

1. 先读取本机已有账本与证据，不重发已确认收件的测试。需要继续桌面动作时核对微信可见、前台与用户当前是否在操作；不要求预选目标群，焦点不满足时停止。
2. 补相似/重名群、目标行不可见、搜索分页及不同显示缩放。当前“完整群名 + 人数”是界面校验，不是持久群 ID；无法唯一确认则不发送。
3. 将原生未读提示单独保存为群级证据，打开群前采集；正文只列文字候选。补 @ 别人、@所有人、引用、同名、多条未读和目标群正在前台时的样本。不得把群级提示推广为每条消息的真 @ 判断，也不能把缺少提示当作历史上没有 @。
4. 解决气泡/发送人切分、短数字漏读、头像噪声，检查跨屏滚动与持续收到后文时的覆盖范围。缺失内容必须显式显示，不用 OCR 推测填补。若业务需要消息级精确 @，须取得并验证相应证据后才接入。
5. 验证已有草稿、剪贴板多格式恢复、中途抢焦点、重启去重和未知发送结果；发送前记账、未知不自动重发。完整通过后再评估接入券单，演示模式不得连接真实微信。公司微信、Wind、共享盘仍需独立现场验证。
