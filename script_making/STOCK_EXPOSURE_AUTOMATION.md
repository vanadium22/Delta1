# 收益互换纯个股敞口：独立邮件任务

公司已反馈原日报和本人收益两图任务更新后均跑通。以后新的定时批次会从原程序路径读取更新后的代码，无需重新保存这两条任务。工作台在批次入队时冻结入口脚本哈希；入队后再更新脚本的旧批次会拒绝执行，按原方式新建批次即可，不修改旧记录。

本次新增第三条独立邮件任务：每天北京时间 **09:20** 触发，生成完成后交给已有Work Automation邮件服务发送。它沿用原日报附件3 `swap_stocks.png` 的纯个股口径。原日报三附件、本人收益两图及原有任务/计划保持。

## 内容和解释

- 来源仍为“收益互换日报 / 风险盈亏统计”，按原同步规则取早于北京时间今日的最新来源日期，不因同步失败回退旧来源。
- 沿用日报**已保存**的阈值、筛选字段和永久剔除名单，保持绝对值阈值含边界。只包含股票，排除指数、股指期货和全部ETF。与原日报在相同来源、阈值和名单下产生的附件3明细及合计一致；不改变risk原“个股和其他ETF”组。
- 正文自动说明来源日期、筛选范围、观察数、带符号Delta总敞口金额、总盈亏和当日盈亏。敞口按原表正负号累加，不跨标的相加Delta数量；这是筛选后子集，不是未经筛选的全台敞口。
- 保留一个普通图片附件 `swap_stocks.png`，含原字段、金额单位、明细及高亮合计。邮件包含纯文本和HTML解释正文；这条任务不附pnl1/risk。原日报的两CID图加普通附件结构不变。
- 空观察子集成功读取后可导出零金额合计和明确说明；来源失败、实际使用缓存缺失不会按零成功。

## 公司更新与前端配置

空闲时更新日报仓库；这一单行命令不启动程序或后台：

```powershell
git -C 'D:\WORKSPACE\MAIN\SwhySc\DeltaOne\project\dashboard' pull --ff-only origin codex/company-apps
```

更新后按原方式打开日报App，在 **统计 → 独立任务邮箱 → 纯个股敞口任务** 填写收件人、可选抄送、主题和正文补充说明，点击保存。多个邮箱用逗号分隔；主题的 `{{date}}` 替换为来源报表日期。正文的口径说明自动生成，补充说明追加在其后。留空收件人时任务不能生成可发送结果。

同一对话框的“本人收益两图任务”页可以修改原单一本人邮箱；原日报收件人仍在原“剔除名单 / 邮件设置”中管理。三者分别存储，不互相继承或覆盖。保存邮箱不发信、不修改计划，下一次任务运行自动读取；已有发送队列中的邮件继续使用该邮件生成时冻结的设置。

阈值修改沿用原操作：在统计页改字段/阈值后点击“生成并记录统计”保存。独立任务同步读取这份已保存条件，不使用未保存的输入框文字。

## 构造和登记09:20任务

构造的程序为 `script_making/swap_stocks_job.py --run`，解释器沿用已验证的日报环境。它独立同步收益互换来源，不依赖原日报先完成，也不加载盈亏统计或D1策略台。三条任务共用目录锁和原工作台队列；09:20为触发时间，实际发送需等前序任务及本任务生成完成。不是另建Windows业务定时器。

可选只读查看完整任务定义，不注册、不运行、不发信：

```powershell
& 'D:\conda\envs\swhy_delta1\python.exe' -B -s -X utf8 'D:\WORKSPACE\MAIN\SwhySc\DeltaOne\project\dashboard\script_making\swap_stocks_job.py' --task-definition
```

配置邮箱后，在已有Work Automation后台正常运行时，执行这一**显式登记新任务**的单行命令。它只通过本机API保存这条每天09:20、启用、成功后发送的新任务，不启动后台，不立即运行，也不修改原日报、本人收益或FOF任务：

```powershell
& 'D:\conda\envs\swhy_delta1\python.exe' -B -s -X utf8 'D:\WORKSPACE\MAIN\SwhySc\DeltaOne\project\dashboard\script_making\swap_stocks_job.py' --register-task --work-root 'D:\WORKSPACE\MAIN\SwhySc\project\work_automation'
```

公司任务Python若与示例不同，替换为原日报实际使用路径。默认API端口8766，已有后台使用其他端口时显式加 `--port <实际端口>`。登记只读取工作台本机Token用于本机请求，不打印或保存Token。没有开启后台时登记会失败，不自行启动它。

返回 `registered` 表示新任务已登记；在工作台“定时子任务”可查看“收益互换纯个股敞口”。同一程序已经登记时返回 `already_registered`，保留其原ID、时间、启停和结果邮件选择，不重复创建或覆盖手工调整。若存在同名不同程序或ID冲突则拒绝写入，先在工作台核对。以后只改邮箱不用再登记或保存任务。首次想手动检查时，可在工作台将此新任务的“程序生成的邮件”改为“仅预览”，运行一次新批次，再按原操作恢复发送；这不会改变已有两条任务。

## 产物和兼容边界

新邮件设置为被忽略的 `script_making/stock_mail.local.json`；仍由工作台原SMTP配置发送，不在日报保存SMTP凭据。独立运行记录、统计记录、完成索引和导出位于实际数据根下的 `statistics/swap_stock_runs`、`swap_stock_records`、`swap_stock_exports`。

出口0成功/复用、1失败、2不完整、3已有任务占用；失败不写本次 `--wa-output` 邮件清单。版本1指纹包含冻结来源哈希、纯个股统计、筛选条件及本任务邮件设置，完整文件集和哈希通过才可复用，旧目录保留。相同输入和设置重复运行、新批次或重启复用原产物与发送记录；每天检查不重复发送未更新来源。改邮箱/主题/说明会作为新的明确邮件设置生成新产物。原日报指纹9和本人收益版本2保持不变。

本次开发仅使用隔离目录、合成Excel、本机测试API和模拟SMTP；未读取正式共享数据、发送真实邮件、登记公司任务或修改公司计划。公司登记由用户执行上述显式命令完成。
