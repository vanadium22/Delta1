# 基差Word和PDF简报

前端使用 **报告与记录 → 一键生成简报并打开PDF**。同页可查看最新Word/PDF、打开保存目录、接入每日自动化、用修正后的图片重排新批次。正式模式默认先尝试Wind增量补缺，取消复选框只用本地；离线模式不联网，合成演示不混入真实简报。后台生成完成后调用默认PDF阅读器。

同一批次生成去分红和不去分红两套Word/PDF。去分红版在`index_futures_basis/exports/recent_brief/行情日/批次/`，不去分红版在批次下的`unadjusted/`。四个稳定入口为`latest.pdf`、`latest.docx`、`latest_unadjusted.pdf`、`latest_unadjusted.docx`。每版默认13页：综合观察、四品种合约总表、跨期表，随后五组图各占两页。两版保留PNG、SVG、明细CSV和来源清单。

## 公司历史数据诊断

若放入多份历史表后生成失败或分位大面积留空，在公司双击模块目录的 `diagnose_recent_brief.cmd`。它读取本机已有行情，按正式简报的流程生成去分红和不去分红两版，结果单独保存在 `exports/recent_brief/diagnostics/<批次>/`。窗口会打印本次 `简报测试报告.txt` 的完整位置，反馈时只需这一份文本。文本列出搜索目录、每份 Excel 的业务日、有效点数及采用条数、按月和实际合约统计的缺口、各分位窗口覆盖数。运行出错时会记录失败位置和异常。

公共分红输入、公共归档、基差设置中的本地分红目录以及 `--dividends` 显式指定的目录支持按年、月等子目录存放历史表。两份文件的内容完全相同时合并采用。每个行情日只使用当时已生效且属于该实际合约的分红。

公司电脑可直接从配置的公盘补收历史表并复测。截止日与旧报告一致时，便于用报告里的缺口总数比较。

```powershell
.\index_futures_basis\diagnose_recent_brief.cmd --as-of 2026-11-20 --backfill-share
```

补收按表内业务日筛选，默认从截止日往前 480 个自然日扫描对应年份目录。用 `--history-from 2026-08-01` 可先补最近的统计窗口。若公司使用自定义公盘目录，可在 `--backfill-share` 后直接传目录。有效原表按哈希归档到公共分红归档的 `share_history`，下一次普通生成和自动任务会读到这些表。公盘读取失败时，报告记录失败并继续用本地已有资料生成。

## 当前合约表与年化分组

四品种00—03共16个合约合成一张原生表、一页展示，按品种合并指数价格栏，以低饱和底色区分品种和档位。另用一张独立表列四品种02−01、03−02共8组跨期，移除不填写的实际合约/到期日列；两腿代码和日期仍保留核对JSON。期货价、分红、基差、年化及指数均保留2位，天数为整数，缺失为—，真实零为0.00。原始计算及CSV/JSON精度保留。

首页按品种写近月00/01等权均值、远月02/03等权均值及远月60个交易日分位。已知当月到期且次月有有效年化时，正文明确列次月值。近月、远月和四档整体三组的均值、分位、样本数和7日变化均保存在`narrative.json`。组分位使用前60个交易日每日同组均值，排除当天，并列半权重。已知T=0的分组日排除，未知期限、缺腿或缺值使该窗分位留空。

同一实际合约或同一跨期组合可用于判断变化。跨期长窗分布按连续组合统计，文字标明样本含换月。跨期样本含换月时跳过端点变化及波动扩张判断。CSV的left为远腿、right为近腿，正值表示远腿高于近腿。重新生成可使用新版口径，重排沿用原图及原数据。

## 五组图片

报告按单合约年化、跨期年化、跨期绝对价差、持仓成交、单合约绝对基差排序，每张完整图分两页，每页两个品种。重排旧批次时沿用旧图和旧顺序。

1. **单合约年化与分位统计**：01—03走势，00保留当前值和统计。右侧按00—03行列当前年化，30/60/120交易日各格显示分位、均值、中位数，均为年化口径；缺完整窗口不显示部分统计，n保留CSV/JSON。当前年化缺失时分位留空，但完整历史的均值/中位数仍保留。
2. **跨期年化与分位统计**：02−01、03−02近六个自然月走势，统计表列前30/60/120/180个交易日的分位、年化均值及中位数。
3. **跨期绝对价差**：两组跨期独立成图，展示近六个自然月，加亮最近5日。
4. **四合约总成交与总持仓**：两版共用总成交及总持仓图。任一腿缺字段时总量留空。
5. **单合约绝对基差**：00—03相对同日现货指数的基差，默认最近60个交易日，可用`--sessions`修改。

卡片仅留合约/指标、当前值及日变化三项；去掉5日变化、分位日变、价格/分红核对小字，完整核对值统一在前表及数据归档。仅最前面的合约/跨期表采用theme.py中的低饱和蓝灰、灰紫、暖灰，无绿色；后续曲线、卡片、成交柱及分位统计表保持示例原配色，不受前表主题影响。

行情是日线close，不是固定前一日或结算价。正式更新按北京时间配置时间（默认15:05）决定截止日，并结合真实交易日历；时间前为上一已收盘交易日，之后尝试包含当日。只读本地/更新失败时，以实际可用数据日期为准；显式截止日不回退、不把旧值移到新日期。工作日16:10自动任务正常更新后通常用当日收盘，假期或缺数时可能更早。

原4类变化摘要仍保存在cards.json、CSV及清单中，按**当前相对前60交易日均值的偏离**选择，依据同序列标准差标准化后排序；同时列当前值、60日均值及当日变动相对历史60次日变绝对值均值的倍数。包括绝对基差、01—03年化、跨期年化、四合约量仓，00不参与年化摘要选择。前60日均值不含当日，日变幅参照60个历史区间需61个历史交易日；历史缺失不缩短窗口。历史标准差为0时按绝对偏离排序，历史日变均幅为0时不算倍数。原每档1/5日变化保留供辅助查看，顶部不再选几天前的变化最大者。

## 计算口径

- 去分红单合约基差为`F+G−S`，不去分红为`F−S`。两版曲线、分位及正文分别计算。跨期两个版本均按远减近，不去分红版直接使用两腿期货收盘价差。
- 单合约年化`(F+G−S)/S×365/剩余自然日×100%`。T≥1均保留实际年化和分位计算，T=0留空；00仅不画年化走势，数据未删除。
- 跨期统一远月减近月：`02−01=(F02+G02)−(F01+G01)`，03−02同理。年化再除同日现货、乘365并除正的“远腿到期日−近腿到期日”自然日间隔，不直接相减两腿年化。原完整Word/原App的远减近图保持原口径。
- 单合约分位取此前30/60/120个**交易日**，跨期另取此前180个**交易日**。排除当日，并列值半权重。完整窗口内已知T=0样本排除并列n；未知日历、到期日或缺输入不能被丢掉冒充完整。覆盖不足显示—。
- 四合约任一腿成交/持仓缺值则对应总量留空。年化变化用百分点，点数用点；CSV保留旧bp列兼容审计。
- 成交量可按实际合约/交易日补共享normalized日线冻结版本的缺口，校验清单/分片哈希，单位为手；不替换期现货价格和持仓。只有Parquet补量需已有pyarrow。

## 命令行与自动化

```powershell
# 默认只读本地，生成Word/PDF，不访问Wind
python -X utf8 -m index_futures_basis.recent_brief
# 单次增量更新后生成，适用于现有自动化App
python -X utf8 -m index_futures_basis.recent_brief --refresh
# 指定真实快照/日期/分红/新批次输出
python -X utf8 -m index_futures_basis.recent_brief --snapshot "D:/资料/raw_market.json" --dividends "D:/资料/基差情况.xlsx" --output "D:/简报/新批次"
# 持续监控本地输入，变化才生成，不下载
python -X utf8 -m index_futures_basis.recent_brief --watch
# 原批次PNG修正后，仅重排为新Word/PDF批次
python -X utf8 -m index_futures_basis.recent_brief --repack "D:/简报/原批次"
```

CMD入口仍复用`python.local.txt`或`SWHY_DELTA1_PYTHON`。每日单次用`start_recent_brief_daily.cmd`；前端“接入每日自动化”在已有Work Automation 0.6.0登记新任务工作日16:10并启用，重复接入保留原ID、计划和启停，不启动其后台、不操作邮件。完整方法见[每天生成](DAILY_GENERATION.md)。本机已实际登记并验证幂等；公司更新后点同一按钮按公司路径登记。

`--refresh`复用原增量服务，再按逐日实际合约补最近80交易日成交量缺口，已有有效数据不重取。未完整更新仍按实际本地数据尽力生成，报告/清单标状态及原因，退出2；完整0。不会把旧行情冒充今日。`--watch`监控SQLite/WAL、分红新增文件和成交量版本，输入不变不重算；失败保留Word/PDF及latest指针，写last_failure.json，输入变化后重试。不要把常驻watch放入工作台串行队列。

绘图在`card_charts.py`、数据在`data.py/metrics.py`、前表在`table_layout.py`、前表配色在`theme.py`、文档布局在`documents.py`，未来可独立调整。重排复制到新批次，不下载/重算/覆盖原批次；清单记录被替换的PNG与文档构建代码哈希。前端、CLI和自动任务共用跨进程生成锁，Word/PDF均完整后才发布latest。

`basis_rank_tables.csv`保存单合约三窗口长表，`calendar_rank_tables.csv`保存跨期四窗口长表。另存60日分位、日频计算、卡片及量仓CSV。`run_manifest.json`版本13记录输入来源/哈希、实际日期、收盘价策略、公式、窗口、摘要基准、自动量仓文字、渲染及输出哈希。真实数据、配置与导出不提交Git。预览仍为2026-10-15真实行情和2026-09-18分红，不代表11月新行情。

## 首页综合观察及分红核验

`narrative.py`的descriptive-tree-v7按去分红年化基差、跨期结构、持仓成交排列。年化段报近远月水平，给远月60日分位，并合并近7个交易日次月同向变化的品种。起止年化相差至少1个百分点才描述，完整且实际合约一致的区间才参与。00距到期1—3天时统一提示近月年化对短期限敏感。

跨期先说明当前远减近的整体方向，再分别选至多1个绝对价差和1个年化重点。比较30/60/120/180个交易日的偏离和分位，优先引用有明显偏离的完整180日样本，再考虑其他完整窗。偏离至少3点或0.4个百分点，且标准化偏离≥1.5或处于10%/90%尾部；波动扩张至少2.5倍且日均变幅达到下限。单合约旧异常特征仅归档，首页不再逐档罗列。历史零波动不除零，无明显异常与样本不足分别说明。量仓按前60日P80%以上判断近期高位，最多2个品种，不将持仓高位直接归因为对冲需求增加。

量仓正文按近7日可比数据描述各品种增减仓及成交方向，再写近期持仓高位。7/30/60日比较特征继续归档：持仓用精确N交易日前总量比较，7日阈值10%、30/60日20%；成交用近7日日均与此前不重叠的N日日均比，阈值25%，最多67日数据，适配80日补量。当前为描述性规则树及模板，未训练预测模型，不作收益预测。

文字与特征保存为narrative.json，并作为原生大字放在Word/PDF最前面；缺历史/缺日历则明确不足，不跳过缺口缩短窗口。普通生成、前端及每日CMD都走相同流程；图片重排保留原数据的总结并移到首页。

`dividend_adjustment_audit.csv`逐行核对公式，记录实际合约、源业务日、生效时间、单元格、哈希及匹配状态。采用的历史表按哈希复制到`dividend_inputs/`。

将历史`.xlsx`放到公共输入`data/dividends/index_futures/inputs/`或其中的`history/`，下一次生成会重新对齐。也可用`--dividends`指定Excel或历史目录。程序同时查读配置的本地输入、公共归档、看板各模式已有的本地缓存。持续生成模式会跟踪这些来源的变化。

快照靠表内业务日、实际合约和分红点数定位记录。日期读 `Sheet1!B1`，分红点数读 G 列。C 列的实际合约尚未缓存、仍显示 `Fetching...` 或重复本行档位时，用 B 列 00–03 档和表内业务日在本地行情库查当天实际合约。表日早于简报统计范围时也可查询已缓存的当天映射，匹配后按实际合约使用分红点数。单份工作簿损坏或表头错误时，简报使用其余可用来源继续生成。构建批次归档本轮实际读到的工作簿字节，兼容生成期间上游替换原文件。诊断文本列出回退映射数量、每份表未采用的原因、各合约缺口首末日期和可显示分位的档位或跨期组合。

每个行情日取截至日线配置时刻已经有效的同一合约最后一笔有效记录（默认北京时间15:05）。看板有归档精确时间时按其时间，只有可靠业务日的旧表按日期。G列缺失沿用同一合约较早的有效值，明确0保留。同一生效时间有不同点数时留空并记录冲突。缺早期表或从未覆盖该合约时断线，窗口覆盖不足留空。新增表从其有效日期起生效。

compact-v2元数据区分新长图和旧图的裁切边界；重排旧图仍使用旧边界，保留原图原数据，文档顺序统一绝对基差最后。均值/中位数须重新生成图片；重排不自动补算旧图统计。PDF字体以TrueType嵌入，中文与合约代码可搜索复制，正常生成仍不依赖Office。
