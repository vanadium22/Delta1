# 基差Word和PDF简报

前端使用 **报告与记录 → 一键生成简报并打开PDF**。同页可查看最新Word/PDF、打开保存目录、接入每日自动化、用修正后的图片重排新批次。正式模式默认先尝试Wind增量补缺，取消复选框只用本地；离线模式不联网，合成演示不混入真实简报。后台生成完成后调用默认PDF阅读器。

输出保存在`index_futures_basis/exports/recent_brief/行情日/批次/`：默认11页A3横向Word/PDF、4张3800像素完整PNG、4份SVG、分段排版图、计算/卡片CSV及来源记录。固定查看`latest.pdf`或`latest.docx`，前端从`latest.json`定位最近成功批次。不生成HTML。综合观察独立置于首页，标题24号、四部分标题17号、正文15号，接着2页为当前合约表（每页两个品种），后面8页为图片与卡片。仅保留简短标题/行情日/收盘价/分红日；页底口径、生成说明、页码和分散文字已移除。Word的摘要和总结为可编辑文字，图可替换；PDF由Matplotlib生成，不依赖本机Office或LibreOffice。

## 当前合约表与年化分组

每品种六行：00—03及02−01、03−02。指数同日价格放在品种标题旁；列连续档位、实际合约、原始期货价/价差、分红G/分红差、去分红基差/调整后价差、年化、到期日、剩余/间隔天数。跨期代码与日期按远、近顺序列两腿，原始价差加分红差等于调整后价差。F/G保留4位，基差及年化2位，缺失为—，真实零为0。Word表格原生可编辑，current_tables.json和清单保留原始精度。

年化只在单个品种内平均，禁止IF/IH/IC/IM混合平均。先判断00—03是否全部接近，否则分别判断近月00/01与远月02/03：完整、同升贴水方向且组内最大差≤1.0个百分点时才写简单平均，差距较大时逐档解释。全四档接近时一句概括；缺失或到期不混入平均，00距到期1—3天提示短期限放大。阈值为overview.ANNUAL_CLOSE_PP，分组证据、是否合并及均值保存在narrative.json。

历史走势和绝对基差异常比较要求同一实际合约/跨期组合；换月区间不连接成市场趋势，缺可比完整30/60日则明确不足或含换月，不把切档跳变写成普遍扩大。年化历史分位仍是连续档位口径，含换月时显式标记。新版必须重新生成才能获得远减近；重排旧批次仍保留原方向及原表数据，不只改旧标签。CSV的left为远腿、right为近腿，正值表示远腿高于近腿；图、均值、日变、分位与文字均按新方向重算。

## 四张核心图片

1. **近期绝对基差与跨期**：四品种00—03绝对基差，以及02−01、03−02点数。保留最近5日高亮与每档当前/变化卡。
2. **单合约年化与历史分位表**：每品种只画01、02、03三条年化走势；00不画年化曲线，也不占顶部单合约年化卡。右侧表格仍按00、01、02、03纵向排列，列当前实际年化、前30日、60日、120日分位；实际合约和T在行头，样本n随分位列显示。没有蜡烛图。
3. **跨期年化与历史分位表**：每品种02−01、03−02两条走势，旁边同式列当前年化及30/60/120交易日分位表。
4. **四合约总成交与总持仓**：每品种00—03总成交柱形、总持仓曲线；量仓文字统一纳入首页综合观察。双轴几何交点不作为信号，按序列自身方向及可比变化判断。

单合约卡片下方列同日指数收盘值、实际期货收盘价、分红G（均保留4位小数，缺失为—、真实零为0.0000），实际合约见卡片标题。跨期卡列指数及远/近两腿原始期货价与各自G，方向按02−01、03−02。前表统一列完整的24条核对数据，替代原首页四个摘要卡。CSV/JSON保留原始精度及交易日，不用调整后的期货价冒充实际报价。

行情是日线close，不是固定前一日或结算价。正式更新按北京时间配置时间（默认15:05）决定截止日，并结合真实交易日历；时间前为上一已收盘交易日，之后尝试包含当日。只读本地/更新失败时，以实际可用数据日期为准；显式截止日不回退、不把旧值移到新日期。工作日16:10自动任务正常更新后通常用当日收盘，假期或缺数时可能更早。

原4类变化摘要仍保存在cards.json、CSV及清单中，按**当前相对前60交易日均值的偏离**选择，依据同序列标准差标准化后排序；同时列当前值、60日均值及当日变动相对历史60次日变绝对值均值的倍数。包括绝对基差、01—03年化、跨期年化、四合约量仓，00不参与年化摘要选择。前60日均值不含当日，日变幅参照60个历史区间需61个历史交易日；历史缺失不缩短窗口。历史标准差为0时按绝对偏离排序，历史日变均幅为0时不算倍数。原每档1/5日变化保留供辅助查看，顶部不再选几天前的变化最大者。

## 计算口径

- 调整后绝对基差`F+G−S`，保留正负号。日常简报每次重读配置的本地分红目录、公共输入目录，以及看板已保存到本机的分红目录/缓存raw日期子目录；按Sheet1!B1业务日期选最新、读取G列缓存点数，不按文件名/mtime、不访问公盘。新简报默认不沿用原App的fixed_file钉住旧文件；显式--dividends仍用于复现。固定快照应用于历史，不冒充真实逐日预测；缺失不猜零，不用旧日有效值覆盖最新日空值。
- 单合约年化`(F+G−S)/S×365/剩余自然日×100%`。T≥1均保留实际年化和分位计算，T=0留空；00仅不画年化走势，数据未删除。
- 跨期统一远月减近月：`02−01=(F02+G02)−(F01+G01)`，03−02同理。年化再除同日现货、乘365并除正的“远腿到期日−近腿到期日”自然日间隔，不直接相减两腿年化。原完整Word/原App的远减近图保持原口径。
- 分位为此前30/60/120个**交易日**，不是固定期限插值；排除当日，并列值半权重。完整窗口内已知T=0样本排除并列n；未知日历、到期日或缺输入不能被丢掉冒充完整。覆盖不足显示—。
- 四合约任一腿成交/持仓缺值则对应总量留空。年化变化用百分点，点数用点；CSV保留旧bp列兼容审计。
- 成交量可按实际合约/交易日补共享normalized日线冻结版本的缺口，校验清单/分片哈希，单位为手；不替换期现货价格和持仓。只有Parquet补量需已有pyarrow。

## 命令行与自动化

```powershell
# 默认只读本地，生成Word/PDF，不访问Wind
python -X utf8 -m index_futures_basis.recent_brief
# 单次增量更新后生成，适用于现有自动化App
python -X utf8 -m index_futures_basis.recent_brief --refresh
# 指定真实快照/日期/分红/新批次输出
python -X utf8 -m index_futures_basis.recent_brief --snapshot "D:/资料/raw_market.json" --dividends "D:/资料/基差情况.xlsx" --output "D:/简报/新批次"
# 持续监控本地输入，变化才生成，不下载
python -X utf8 -m index_futures_basis.recent_brief --watch
# 原批次PNG修正后，仅重排为新Word/PDF批次
python -X utf8 -m index_futures_basis.recent_brief --repack "D:/简报/原批次"
```

CMD入口仍复用`python.local.txt`或`SWHY_DELTA1_PYTHON`。每日单次用`start_recent_brief_daily.cmd`；前端“接入每日自动化”在已有Work Automation 0.6.0登记新任务工作日16:10并启用，重复接入保留原ID、计划和启停，不启动其后台、不操作邮件。完整方法见[每天生成](DAILY_GENERATION.md)。本机已实际登记并验证幂等；公司更新后点同一按钮按公司路径登记。

`--refresh`复用原增量服务，再按逐日实际合约补最近80交易日成交量缺口，已有有效数据不重取。未完整更新仍按实际本地数据尽力生成，报告/清单标状态及原因，退出2；完整0。不会把旧行情冒充今日。`--watch`监控SQLite/WAL、分红新增文件和成交量版本，输入不变不重算；失败保留Word/PDF及latest指针，写last_failure.json，输入变化后重试。不要把常驻watch放入工作台串行队列。

绘图在`card_charts.py`、数据在`data.py/metrics.py`、文档布局在`documents.py`，未来可独立调整。重排复制到新批次，不下载/重算/覆盖原批次；清单记录被替换的PNG与文档构建代码哈希。前端、CLI和自动任务共用跨进程生成锁，Word/PDF均完整后才发布latest。

`basis_rank_tables.csv`和`calendar_rank_tables.csv`保存三窗口长表；另存60日分位、日频计算、卡片及量仓CSV。run_manifest.json版本9记录输入来源/哈希、实际日期、收盘价策略、公式、窗口、摘要基准、自动量仓文字、渲染及输出哈希。真实数据、配置与导出不提交Git。预览仍为2026-10-15真实行情和2026-09-18分红，不代表11月新行情。

## 首页综合观察及分红核验

`narrative.py`的descriptive-tree-v4参考用户人工改写，按“整体节奏—当前状态—近期变化—少数重点”组织四部分文字。合并同向品种，绝对基差覆盖00—03、年化覆盖01—03，至少三分之二期限同向才称多数。优先完整60日走势，否则明确30日；5日中位数与噪声阈值支持“扩大—收敛—再扩大”三段形态，并独立判断多数期限近一周是否平稳，不照抄人工例句及当日报数。年化补充各品种多数合约的60日低/高分位状态、次月合约近7日年化贴水扩大（超过1个百分点且区间不含换月）。

再按30/60交易日的当前偏离/分位及近7日日均变幅扩张选各至多1个合约，跨期绝对/年化各至多1个，减少数字堆叠。偏离至少3点或0.4个百分点，且标准化偏离≥1.5或处于10%/90%尾部；波动扩张至少2.5倍且日均变幅达到上述下限。历史零波动不算无穷倍。无明显异常/样本不足分别说明，不强行选最大者，不把低年化正值称为深贴水。量仓另报当前总持仓处于前60日P80%以上的最多2个品种；不把持仓高位直接归因为对冲需求增加。

量仓先概括近7日各品种，再从7/30/60日比较中最多展开一个持仓和一个成交变化。持仓用精确N交易日前总量比较，7日阈值10%、30/60日20%；成交用近7日日均与此前不重叠的7/30/60日日均比较，阈值25%，最多67日数据，适配既有80日补量。当前为可解释描述性规则树及模板，未训练预测模型，不作收益预测；窗口、特征、阈值与入选项保存以便后续修正。

文字与特征保存为narrative.json，并作为原生大字放在Word/PDF最前面；缺历史/缺日历则明确不足，不跳过缺口缩短窗口。普通生成、前端及每日CMD都走相同流程；图片重排保留原数据的总结并移到首页。

逐行校验调整后基差减未调整基差等于分红G，导出dividend_adjustment_audit.csv；原分红字节另存dividend_input_snapshot.xlsx并核验源哈希，防止绘图途中输入变化混用。本机上一版已使用分红：00的G为0不代表未读取分红；当前正式输入和看板本地缓存最新均为2026-09-18，预览仍基于2026-10-15行情。

公司分红自动落地目录修复：发现源覆盖dashboard/localsetting/app、numeric_excel及旧localsetting三套native.json，各配置的overview_dividend_cache和默认overview_dividends/raw/业务日缓存均参与，兼容UTF-8 BOM、相对仓库路径及本地overview_dividend_source_dir；不访问UNC或映射公盘、不启动看板同步任务。监控同时跟踪三份配置和新增Excel，仍按Sheet1!B1选最新，保持同日冲突校验。分红早于行情超过7自然日时抬头明确提示，清单记录age_calendar_days；源缺失也显式提示，不再只显示旧日期让人误以为已用当天分红。公司最新文件实际接入须公司重新生成验证，本机不声称已取得公司新文件。
