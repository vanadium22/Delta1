# 历史行情下载

从 `P:\project\swhy\project\market_data\start_app.cmd` 启动，在左侧进入「交易数据下载」。也可运行 `start_app.cmd --page trading` 直接进入。
界面启动不连接数据库、不自动下载；实时采集和历史下载各自运行、各自停止。关闭窗口时等待当前请求和文件保存完成。

其他项目如何调用、按批次读取与维护索引，统一见 [公共数据接入说明](../../docs/DATA_ACCESS.md)。示例代码见 [history_client.py](../../examples/history_client.py)。

## 操作

1. 输入一个或多个代码，每行一个，或用逗号分隔。例如 `AU2612.SHF`、`AU.SHF`、`AU00.SHF`、`600000.SH`、`000001.SH`、`588000.SH`。
2. 选择数据类型。默认自动识别；`000001.SH` 是指数，`000001.SZ` 是股票。可手动指定股票、指数或 ETF。
3. 点击「日历」选择开始、结束日期，也可输入 YYYY-MM-DD，两端包含；常用范围「昨天 / 近30日 / 本年」截止昨天。非交易日由后端交易日历排除，日历按钮不是交易所节假日表。选择频率，无记录的日期不生成数据文件。
4. 选择获取方式和生成来源，见下表。OHLC、成交量和成交额可逐项勾选，期货可选 OI；**日频不提供盘口**。其余频率可选 0–3 档，包括每档买卖价格及挂单量。不下载内盘/外盘或主动买卖成交量。
5. 选择保存文件夹。默认 `T:\inani\下载\AI\DolphinDB`。
6. 点击「检查与预览」检查整个范围的逐日映射和有无记录。日频每个标的最多读取 60 个可用交易日，日内频率最多读取 3 个可用交易日，每日先展示 100 行样本；未读取日期显示待校验。预览仅保存请求记录，不落地行情文件。
7. 点击「开始下载」。按标的、交易日依次保存。可以切换页面或停止任务；停止会完成当前日的写盘和校验，保留已完成结果。

连接沿用 `P:\project\swhy\project\dolphindb_data\config\connection.local.json`。修改数据库密码后同步更新该文件；支持 `DDB_PASSWORD` 环境变量覆盖。
Python SDK 使用原生 TCP+SSL，遵循操作系统内网 VPN 路由，不经过 HTTP 代理。

## 缺失数据和强制生成

| 获取方式 | 行为 |
| --- | --- |
| 原始优先，缺失补齐（默认） | 保留目标频率原有有效值；缺少整日、周期或字段时从更细频率补齐，并记录补齐字段。 |
| 仅原始数据 | 只读取所选频率原表；没有的日期和字段明确标记，不跨频率补齐。 |
| 仅用其他频率生成 | 跳过目标频率原表，完全由指定的更细来源生成，即使原表有数据。 |

生成来源可选择「自动选择」「1分钟」「原始快照」。日线和大于一分钟的周期自动先尝试 1 分钟，再尝试快照；1 分钟和秒桶只能从快照生成。不能从分钟数据还原秒级行情或原始快照。

- 日频：按 `TradingDate` 合并归属于该交易日的夜盘和日盘；OHLC 取首值/最高/最低/末值，期间量额求和，OI 取末值。校验首尾时点与累计成交量，不通过的字段保留为空。
- 日频使用快照时：取收盘后末条记录的当日累计 OHLC/成交量/成交额和 OI，不用采样最新价推断全天最高最低。
- 较长分钟线：按交易分钟累计，跳过节间休市，夜盘和日盘分别计时；开盘点单独保留，时间标签在周期末。AU 的 60 分钟日盘标签为 09:00、10:00、11:15、14:15、15:00，与实测源表一致。
- 股票、ETF、指数由分钟生成日线或较长分钟线时，只使用常规交易时段，剔除源表 15:06–15:30 的盘后记录。国债期货收盘检查使用 15:15。
- 秒桶和由快照生成的分钟线仅代表快照观测；没有观测的时段不造记录。盘口不得使用未来快照，挂单量也不能借用不同报价对应的数量。

无记录、映射缺失、字段空值和当日尚未完成分别显示；当日日线在 16:00 前标记待完成。全字段有值只说明本次请求的检查通过，不构成交易所行情完整性的独立认证。源端缺少整段行情时，不能保证仅凭现有数据全部补回。

## 查看结果

顶部请求记录可切换最近 30 次请求；旧请求与新请求的内容互不混杂，重启后仍可回看。

- **行情数据**：真实表格。可按列排序、全文筛选、复制选中行；每页 100 行，上方直接点击「行情 / 盘口 / 来源 / 全部」切换列组。盘口优先展示时间、合约及买卖价量；横向滚动查看其余档位，空值显示 `—`。日频、指数、未选择盘口时给出明确说明。
- **日期与合约**：逐标的、逐交易日显示实际合约、当日映射、原始/生成/无记录/待完成状态。
- **来源与文件**：每个结果的实际来源表、行数、耗时和完整文件路径。选中后点击「读取选中文件」，可分页查看本地 Parquet 全部记录；「整个请求样本」回到请求汇总。
- **运行日志**：只显示当前选中请求的日志。点击「字段来源」可查看每个字段来自哪张表、使用哪个源字段、生成/补齐行数及空值数。

请求汇总样本最多显示 10,000 行，完整下载不受这个界面上限影响。当前请求的取消操作不会停止实时页采集。

## 数据来源与频率

源目录 `catalog.json` 于 2026-10-09 从当前账号可见表中核验了 75 张相关表的结构。目录可用不代表每只证券、每个日期都有数据；具体范围按选中代码查询。

| 类别 | 来源 | 可选频率 | 盘口 / OI |
| --- | --- | --- | --- |
| 上期、大商、郑商、能源中心期货 | CSMAR 分时、L1/L2 快照；Wind 日线 | 1/3/5/10/15/30/60 分钟、日线、原始快照、1/5 秒桶 | 盘口按实际档位；OI |
| 中金所股指/国债期货 | `ff_l2_*` / `tf_l2_*`；Wind 日线 | 同上 | 盘口按实际档位；OI |
| 广期所期货 | `future_l2_taq_gfex`；Wind 商品日线 | 原始快照、1/5 秒桶、日线 | 当前目录没有原始分钟表；不假装存在 |
| 沪深股票、ETF | `l1_trdmin*_sh/sz`、`l1_taq_sh/sz`；Wind 日线 | 分钟、日线、原始快照、1/5 秒桶 | 三档盘口视源数据实际可用性 |
| 沪深指数 | 共用沪深行情表，通过代码选择；Wind 指数日线 | 分钟、日线、原始快照、1/5 秒桶 | 无真实委托盘口，无 OI |

典型表：

- AU 分钟：`dfs://ods_olap_m_csmar/future_l1_trdmin1_shfe`。
- AU L2：`dfs://ods_tsdb_d_hash20_csmar/future_l2_taq_shfe`。
- 上海分钟：`dfs://ods_tsdb_d_hash20_csmar/l1_trdmin1_sh`。
- 上海快照：`dfs://ods_tsdb_d_hash20_csmar/l1_taq_sh`。
- 深圳分钟：`dfs://ods_tsdb_d_hash10_csmar/l1_trdmin1_sz`。
- 连续映射：`dfs://ods_tsdb_wind/cfuturescontractmapping`。

原始快照中的 `session_open/high/low` 是当日累计价格，`last` 是最新价，不能当作秒线 OHLC。
1 秒、5 秒使用原始快照在本地聚合：左闭右开 `[t,t+N秒)`，时间标记为桶起点，最新价取 OHLC，源分笔期间成交量/额求和，OI 和盘口取最后一条（保留该条的空值）。无快照的桶不补齐。
沪深样本快照通常约 3 秒一条，因此选择 1 秒桶也不会得到每秒一条真实行情。
原始日内导出保留源表盘前、盘后记录；生成日线和较长分钟线按上文交易时段处理。`TradingDate` 的归属与 `TradingTime` 自然日可能不同。

AU 的 L1 样本二、三档价格为空。期货选择多档时，存在 L2 来源则秒桶/快照使用 L2；分钟 OHLCV 保留原分时值，盘口用不晚于分钟标签的最后一条 L2 快照匹配，最大间隔 60 秒，保留 `book_timestamp`。没有可用盘口时为空，不使用未来快照、不跨长休市区间填充。
二、三档并非任何时刻都有报价；无效价格对应的挂单量也置空。日线与指数不输出盘口；缺少字段或整日全空的字段会在预览详情和文件说明中标明。

**导出格式版本 2 统一量额单位**：成交额为元；股票成交量为股、ETF 为份、指数和期货为手、期货 OI 为手。Wind 股票/ETF 日线成交量乘 100；Wind 日线成交额，期货乘 10,000，其他类别乘 1,000；不额外乘合约乘数。来源单位换算保存在 JSON。旧版本文件保留原单位，请不要直接与新文件混合。价格和连续合约均未复权，不同来源的成交额舍入精度仍可能不同。

## 主力与连续

- `AU.SHF` 等无月份主力：默认按**当日历史 main** 映射解析，使用 `Z:\Project_data\future_investment\data\raw\day\main\month_contract_code.pkl`。也可显式选择「前一交易日主力」用于原有交易口径；实时页规则维持原有口径。
- `AU00.SHF`、`AU01.SHF` 等两位连续代码：默认读取同一数据根目录的 `raw/day/next/+0`、`+1` 等当日 `month_contract_code.pkl`；这里是按交割序列排列的 next，不能理解为成交量第二大的次主力。映射为空时失败，不猜测。
- 连续代码也可显式选「Wind历史映射」，按照 `cfuturescontractmapping` 的 `STARTDATE/ENDDATE` 有效区间解析；缺失或冲突会失败。该数据库映射包含后续修订，不是点时快照。
- `AU2612.SHF` 等具体合约直接查询。保存的 `symbol` 是请求代码，`source_symbol` 是真实合约；JSON 还记录映射日期和规则。
- 本地日历/主力映射路径沿用实时页设置；超出日历覆盖范围、所选日期缺少映射都会报错。历史同日映射是已有日终结果，未声称在当日开盘前已经可知。主力拼接保留换月跳空，不做后复权。

2026-10-08 实测：`AU.SHF → AU2612.SHF`，`AU00.SHF → AU2610.SHF`，`AU01.SHF → AU2611.SHF`，`IF00.CFE → IF2610.CFE`。

2026-08-13～2026-10-08 的 AU 主力共 35 个交易日：9 月 24 日仍为 AU2610，9 月 28 日起为 AU2612。原生日线只有 10 月 8 日，其他 34 天可由分钟生成；下载后逐日 OHLC、成交量和 OI 与 Z 盘 main 日线全部一致。

## 文件与恢复

保存结构：`保存目录/historical/批次时间_唯一编号/请求标的/频率/YYYY-MM-DD.parquet`。
每个数据文件带同名 JSON，记录 `schema_version: 2`、实际合约、来源表、生成规则、逐字段来源、单位换算、空值数、时间范围、文件大小与 SHA-256。行情列含 `data_origin`（native/derived/mixed）、`filled_fields` 和 `quality`。批次 `run.json` 记录整个日期范围的覆盖、完成、失败和无数据项。
Parquet 写入 `.partial` 后回读逐值校验，成功才改名。日期列统一为纳秒精度。下载索引自动登记；默认目录下登记到 `T:\inani\下载\AI\下载索引.md`，自选目录下登记到该目录的索引。
停止和失败不会删除完成文件。重新运行会建立新批次，不覆盖旧文件；可以按失败的日期和代码单独重跑，不把中断批次误标为完整。
单标的一日原始记录超过 50 万行时明确报错，需进一步拆块；不会静默截断。桌面预览和运行日志有显示上限，磁盘数据不受此限制。
